## 1. 愿景与核心定位
构建一款“客户端确定性仿真 + 放置循环 + 构筑深度”的 Web RPG。  
新定位要点：  
- 战斗完全在前端确定性运行；服务器承担最小职责（存档、签名、开战/结算、掉落裁定、助战政策校验）。  
- 以“异步助战影分身”塑造组队感，低成本实现社交参与与反馈。  
- 支持离线收益与在线一致性（同一仿真核），但经济结果以服务器结算为准。

特征：  
- 时间驱动（Event Time Jump 或固定 Tick）统一推进循环（战斗、采集、生产、资源层叠）  
- 双轨战斗节奏（Attack Track + Special Track）+ 双资源 / 叠层 Buff，塑造职业差异与构筑选择  
- 助战政策（V1：等级上限）保证平衡，后续可加缩放/占比上限/光环模式  
- Map / Region 解锁 → 进程感 + 内容引导  
- 数据驱动（技能 / 掉落 / 条件 / 配方 / 装备词条）降低新增成本

## 2. 玩家核心循环 (Core Loops)
| 层级 | 时间尺度 | 描述 |
|------|----------|------|
| 短循环 | 秒 ~ 分钟 | 进入地图→本地战斗仿真→资源生成→技能释放→客户端结算动画→向服务器提交摘要换取掉落 |
| 中循环 | 0.5~5小时 | 选择助战影分身→装备调整/重铸→重复刷图→离线回收 |
| 长循环 | 天 / 周 | 声望推进、周常任务、职业转职、装备优化、地图解锁、助战荣誉与积分（可选） |
| 赛季循环 (未来) | 月+ | 赛季重置 / 限时事件 / 排行榜（摘要上报型） |

## 3. 架构与工程原则
- Client-Sim, Server-Verified：战斗、数值与RNG在客户端确定性推进；服务器负责开战签发（runId+seed）、结算审计与掉落裁定。  
- Deterministic 时间推进：固定 Tick（建议100ms）或事件时间跳跃（PriorityQueue）；统一 RNG 消耗序，支持回放/重算。  
- Data-Driven：配置（JSON/数据表）+ 版本号管理；战斗内 VersionPin。  
- 事件导向（客户端域内）：SkillCast / ResourceOverflow / PlanCompleted / SegmentFlushed。  
- 可测试：可注入 GameClock 与 RNGContext；支持战斗摘要（Digest）对比。  
- 监控优先：审计通过率、助战选择与通过率、掉落裁定延迟、异常摘要分布。  
- 安全与反滥用：助战政策版本、摘要合理性窗口、掉落仅服务器裁定、run 幂等。  
- 小步演进：MVP 先上线助战等级上限，后续再加缩放/占比上限/光环。

## 5. 战斗系统 (双轨 + 事件调度 + 聚合)
说明：战斗在客户端运行，保证确定性；服务器不参与逐事件计算，仅在开战/结算时交互。

### 5.1 核心概念
- BattleInstance：客户端运行态根对象  
- TrackState：AttackTrack（受急速）、SpecialTrack（职业节奏，默认不受急速）  
- 时间推进：  
  - 方案A：固定 Tick（如 100ms），逻辑与渲染解耦；  
  - 方案B：事件时间跳跃（PriorityQueue，按 nextTriggerTime）。  
- 事件类型：AttackTick / SpecialPulse / SkillReady / BuffExpire / PlanTransition / SegmentFlush（客户端本地）

### 5.2 战斗循环（伪流程）
1. 从调度器取最近事件或推进到下一个 Tick  
2. AdvanceClock → 执行事件 → 更新资源/伤害/Buff/冷却  
3. 自动施放：按槽位优先级检查成本与CD → 施放  
4. 写入 Segment 缓冲（聚合原子事件）  
5. 达到阈值（事件数≥N 或时间≥M）→ 产出 SegmentSummary（仅本地存，用于 Digest）

### 5.3 CombatSegment / Digest
- 作用：减少上传成本，便于审计与回放  
- 字段（建议）：startTime/tick, endTime/tick, eventCount, damageBySource, resourceFlow, buffUptime, rngSeedRange  
- 战后生成 BattleDigest（总伤、时长、施放次数、rngSeedStart/End、关键计数）

### 5.4 RNG 管理（客户端）
- StartBattle 注入 Seed（服务器签发），战斗内记录 seedIndex 消耗区间  
- 统一 RNGContext.Next() 消费顺序，保证可回放与一致性

## 9. 离线收益 & 快进模拟
| 步骤 | 描述 |
|------|------|
| 1 | offlineDuration = min(realOffline, cap 可配) |
| 2 | 客户端 OfflineFastForwardEngine：用同一调度推进 |
| 3 | 生成聚合摘要（资源、产出期望） |
| 4 | 上线后按服务器规则提交“离线结算请求”（可配：仅战利品/部分活动） |
| 审计 | 服务器可设置离线上限、最小时长/事件数、频率限制，拒绝异常摘要 |

备注：离线直发掉落仍由服务器裁定；为降低风险，MVP 可先仅支持“在线战斗结算”。

## 10. 组队感与助战（Async Co-op）
- 形态：从服务器获取他人 BuildSnapshot（签名），在本地生成“影分身”AI 同伴。  
- 掉落归属：仅借用者；被助战者获得积分/荣誉（可选）。  
- 平衡（V1 已启用）：助战等级上限  
  - helper.level ≤ borrower.level + 5  
  - 可选区域门槛（默认关闭）：helper.level ≤ region.midLevel + 2  
  - StartBattle 强校验；Assist 列表客户端预筛选与禁用提示。  
- 后续（V2+）：缩放（final_scale）、伤害占比上限（maxShare）、光环模式（极差时仅提供 Buff）。

## 附录 A：固定 Tick 最小循环伪代码
```
const TICK_MS = 100
loop:
  now = clock.Now()
  if now < nextTick: render.Interpolate(); continue
  nextTick += TICK_MS
  foreach (track in tracks) track.TryTrigger(now)
  events = scheduler.CollectDue(now) // 或按固定顺序执行
  foreach (e in events) e.Execute(ctx)
  AutoCast.TryCast(ctx)
  segment.Add(events)
  if segment.ShouldFlush(): segment.Flush()
```
