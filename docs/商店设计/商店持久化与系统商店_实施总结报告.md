## 二、功能实现详情

### 2.1 Phase 1 - 持久化修复

#### 问题描述
`UpdateCharacterRequest` DTO 中缺少 `PurchaseState` 字段，导致商店限购状态无法通过心跳/手动保存机制持久化到服务器。

#### 解决方案
通过 3 处最小代码改动，将商店限购状态无缝接入现有保存机制：

| 文件 | 修改内容 |
|-----|---------|
| `CharacterRequest.cs` | 添加 `PurchaseState?` 字段 |
| `CharacterService.cs` | 在请求中发送 `PurchaseState` |
| `CharacterController.cs` | 接收并保存 `PurchaseState` |

#### 单元测试
新增 5 个测试用例：
- `PurchaseState_SerializesToJson_Correctly`
- `PurchaseState_PreservedAcrossPurchases`
- `UpdateCharacterRequest_IncludesPurchaseState`
- `PurchaseState_EmptyState_InitializesCorrectly`
- `PurchaseLimitTracker_DailyReset_ClearsPerDayCounts`

### 2.2 Phase 2 - 账号级限购分离

#### 问题描述
账号级限购（PerAccountCounts）存储在角色的 `PurchaseState` 中，但用户有多个角色时，每个角色的数据是独立的，导致账号限购可被其他角色绕过。

#### 解决方案
将账号级限购数据分离到 User 表，实现跨角色共享。

#### 新增文件

| 文件 | 说明 |
|-----|------|
| `AccountPurchaseState.cs` | 账号级购买状态模型 |
| `UserController.cs` | 用户 API 控制器 |
| `UserService.cs` | 客户端用户服务 |
| `AddAccountPurchaseState.cs` | 数据库迁移 |

#### API 端点

| 方法 | 路径 | 说明 |
|-----|------|------|
| GET | `/api/User/purchase-state` | 获取账号购买状态 |
| PUT | `/api/User/purchase-state` | 更新账号购买状态 |

#### 单元测试
新增 7 个测试用例：
- `AccountPurchaseState_SerializesToJson_Correctly`
- `AccountPurchaseState_GetCount_ReturnsZeroForMissingItem`

### 2.5 Bug 修复

#### Bug 1：新用户默认槽位问题
- **问题**：新注册用户仍有 3 个角色槽位
- **原因**：`AuthController.cs` 创建用户时未显式设置 `MaxCharacterSlots`
- **修复**：显式设置 `MaxCharacterSlots = userConfig.DefaultCharacterSlots`

#### Bug 2：购买后限购未生效
- **问题**：购买角色槽位后，限购计数未持久化
- **原因**：EF Core 值转换器不会自动检测复杂对象内部变更
- **修复**：显式标记属性为已修改 `_context.Entry(user).Property(u => u.AccountPurchaseState).IsModified = true;`

#### Bug 3：购买后 UI 未更新
- **问题**：购买角色槽位后，创建角色组件未更新可用槽位数
- **原因**：`OnSlotPurchased` 回调未刷新 `CharacterCreation` 组件
- **修复**：添加 `RefreshAsync()` 方法并在回调中调用

## 七、已知限制与后续建议

### 7.1 已知限制

1. **配置静态加载**：运行时修改 JSON 文件不会生效，需重启服务器
2. **缺少购买记录**：没有记录购买历史，无法追溯问题或做数据分析

### 7.2 后续优化建议

1. **热加载配置**：实现配置文件变更监听，支持运行时重载
2. **购买历史记录**：添加 PurchaseHistory 表，记录每次购买详情
3. **服务端限购校验**：在服务端也进行限购验证，防止客户端篡改
4. **批量购买优化**：支持一次购买多个商品，减少 API 调用次数
