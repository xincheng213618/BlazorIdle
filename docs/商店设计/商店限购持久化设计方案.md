# 商店限购持久化设计方案

版本：v1.0  
日期：2025-11-25  
作者：@copilot

---

## 一、问题分析

### 1.1 现状

通过分析代码，发现当前商店限购系统存在以下问题：

**持久化断层**：`UpdateCharacterRequest` DTO 中缺少 `PurchaseState` 字段

```csharp
// 当前 UpdateCharacterRequest 中的字段（摘要）
public class UpdateCharacterRequest
{
    public int? MaxHp { get; set; }
    public BlazorIdle.Shared.Models.Inventory? Inventory { get; set; }
    public Dictionary<string, ProfessionProgress>? Professions { get; set; }
    public HashSet<string>? LearnedSkills { get; set; }
    public Dictionary<string, EquippedSkillsConfig>? EquippedSkillsByProfession { get; set; }
    // ❌ 缺少 PurchaseState
}
```

**结果**：
- `CharacterData.PurchaseState` 在客户端正常运作
- 心跳保存和手动保存时，`PurchaseState` 不会发送到服务器
- 玩家刷新页面或重新登录后，限购计数会丢失
- 数据库中的 `PurchaseState` 字段始终为空或初始值

### 1.2 影响范围

| 限购类型 | 影响 |
|---------|------|
| 每日限购 (PerDay) | 刷新后计数丢失，可被绕过 |
| 角色限购 (PerCharacter) | 刷新后计数丢失，可被绕过 |
| 账号限购 (PerAccount) | 刷新后计数丢失，可被绕过 |
| 每日重置日期 (LastDailyReset) | 刷新后丢失，重新计算 |

## 二、解决方案设计

### 2.1 设计目标

1. **无缝集成**：复用现有心跳保存和手动保存机制，无需新增保存逻辑
2. **最小改动**：只修改必要的 DTO 和 Controller 代码
3. **向后兼容**：不影响现有功能，PurchaseState 为可选字段
4. **统一管理**：所有角色数据通过同一管道持久化

### 2.2 修改方案

#### 2.2.1 修改 UpdateCharacterRequest DTO

**文件**: `BlazorIdle.Shared/DTOs/CharacterRequest.cs`

```csharp
public class UpdateCharacterRequest
{
    // ... 现有字段 ...

    /// <summary>
    /// 购买状态 - 追踪商店限购计数和重置时间 (Step 4)
    /// Purchase state - tracks shop purchase limits and reset times
    /// </summary>
    public BlazorIdle.Game.Purchase.PurchaseState? PurchaseState { get; set; }
}
```

#### 2.2.2 修改 CharacterController

**文件**: `BlazorIdle.Server/Controllers/CharacterController.cs`

在 `UpdateCharacter` 方法中添加：

```csharp
// 更新购买状态 (Step 4)
// Update purchase state
if (request.PurchaseState != null)
{
    character.PurchaseState = request.PurchaseState;
}
```

#### 2.2.3 修改 CharacterService

**文件**: `BlazorIdle/Services/CharacterService.cs`

在 `UpdateCharacterAsync` 方法中添加：

```csharp
var request = new UpdateCharacterRequest
{
    // ... 现有字段 ...

    // 购买状态 (Step 4)
    // Purchase state
    PurchaseState = character.PurchaseState
};
```

### 2.3 数据流图

```
游戏中购买商品
    ↓
PurchaseService.Purchase()
    ↓ 更新内存中的
PurchaseLimitTracker.IncrementCount()
    ↓
CharacterData.PurchaseState 已更新
    ↓
OnItemPurchased 回调 / 或等待定时器
    ↓
HeartbeatService.UpdateCharacter() / SaveNowAsync()
    ↓ 构建请求
CharacterService.UpdateCharacterAsync()
    ↓ 包含 PurchaseState
HTTP PUT /api/Character/{id}
    ↓
CharacterController.UpdateCharacter()
    ↓ 保存到数据库
GameDbContext.SaveChangesAsync()
    ↓
PurchaseState 持久化成功 ✅
```

### 3.1 文件修改清单

| 文件 | 修改类型 | 说明 |
|-----|---------|------|
| `BlazorIdle.Shared/DTOs/CharacterRequest.cs` | 新增字段 | 添加 `PurchaseState?` 属性 |

### 3.2 代码变更量估计

- **新增代码行数**: ~10 行
- **修改代码行数**: ~5 行
- **影响文件数**: 3 个

### 3.3 风险评估

| 风险 | 级别 | 缓解措施 |
|-----|------|---------|
| 数据兼容性 | 低 | PurchaseState 为可选字段，null 时不更新 |
| 序列化问题 | 低 | 使用现有 EF Core JSON 配置，已验证可行 |
| 并发冲突 | 中 | 保留现有乐观锁机制，最后写入者获胜 |

## 六、后续优化建议

### 6.1 短期优化（可选）

1. **购买后立即保存**
   - 在 `ConsumableShopPanel.PurchaseItem` 中购买成功后触发立即保存
   - 防止购买后意外关闭浏览器导致数据丢失

```csharp
// ConsumableShopPanel.razor
if (result.Success)
{
    // 触发保存（可选：立即保存或依赖心跳）
    if (OnItemPurchased.HasDelegate)
    {
        await OnItemPurchased.InvokeAsync();
    }
    // 可考虑添加：await HeartbeatService.SaveNowAsync();
}
```

2. **账号级限购分离**
   - 当前账号限购存储在角色的 PurchaseState 中
   - 未来可考虑分离到用户级别的 AccountPurchaseState

### 6.2 长期优化

1. **服务端验证**
   - 添加服务端限购验证，防止客户端篡改
   - 实现乐观锁机制处理并发

2. **历史记录**
   - 添加 PurchaseHistory 表记录每次购买
   - 支持交易查询和回滚

---

## 七、总结

本设计方案通过 **3 处最小代码改动**，将商店限购状态无缝接入现有的心跳保存和手动保存机制，实现统一的持久化管理。

**优点**：
- ✅ 代码改动量极小（~15行）
- ✅ 完全复用现有保存架构
- ✅ 向后兼容，不影响现有功能
- ✅ 自动随心跳定时保存，无需额外触发

**实施工期**：约 0.5-1 小时
