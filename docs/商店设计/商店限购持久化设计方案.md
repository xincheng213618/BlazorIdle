## 一、问题分析

### 1.1 现状

通过分析代码，发现当前商店限购系统存在以下问题：

**持久化断层**：~~`UpdateCharacterRequest` DTO 中缺少 `PurchaseState` 字段~~ ✅ 已修复

```csharp
// ✅ 已添加 PurchaseState 字段 (Step 4 Phase 1)
public class UpdateCharacterRequest
{
    // ... 其他字段 ...
    public BlazorIdle.Game.Purchase.PurchaseState? PurchaseState { get; set; }
}
```

~~**结果**~~：
- ~~`CharacterData.PurchaseState` 在客户端正常运作~~
- ~~心跳保存和手动保存时，`PurchaseState` 不会发送到服务器~~
- ~~玩家刷新页面或重新登录后，限购计数会丢失~~
- ~~数据库中的 `PurchaseState` 字段始终为空或初始值~~

✅ **已修复**：PurchaseState 现在通过心跳保存和手动保存正常持久化。

### 1.3 账号级限购的架构问题 ✅ 已解决

~~当前设计存在一个**更深层的架构问题**~~：

**问题描述**：
- `PurchaseState` 存储在 `CharacterData` 中（角色级别）
- 但 `PerAccountCounts`（账号限购）本应是用户级别的数据
- 如果用户有多个角色（如角色A和角色B），每个角色有独立的 `PurchaseState`
- 当角色A购买了账号限购商品，角色B 的 `PurchaseState` 中不会有这条记录
- **结果**：账号限购可被绕过（用其他角色重复购买）

**示例**：
```
账号限购商品 X（限购1次）

角色A购买 → A.PurchaseState.PerAccountCounts["userId:X"] = 1
角色B查询 → B.PurchaseState.PerAccountCounts["userId:X"] = 0  ← 无记录！
角色B购买 → 购买成功（绕过限购）
```

**当前代码位置**：
- `PurchaseLimitTracker.GetAccountCount()` 使用 `accountId:itemId` 作为键
- 但读取的是角色级别的 `_state.PerAccountCounts`

### 1.4 解决账号级限购的方案选项

| 方案 | 描述 | 优点 | 缺点 | 复杂度 |
|-----|------|------|------|--------|
| **A. 用户表存储** | 在 User 表添加 AccountPurchaseState 字段 | 架构正确；数据隔离清晰 | 需新增 API；改动较大 | 高 |
| **B. 角色间同步** | 加载角色时合并所有角色的 PerAccountCounts | 改动较小；复用现有存储 | 逻辑复杂；可能有并发问题 | 中 |
| **C. 服务端校验** | 购买时服务端查询所有角色的限购状态 | 安全可靠；防篡改 | 需服务端逻辑 | 中高 |
| **D. 暂不处理** | 先实现角色级持久化，后续迭代 | 快速交付；渐进改进 | 账号限购暂时可被绕过 | 低 |

**推荐方案**：

短期（本次实施）：选择 **方案 D**，先解决主要问题（持久化断层）
中期（后续迭代）：选择 **方案 A**，在 User 表添加 `AccountPurchaseState` 字段

## 二、解决方案设计

### 2.1 设计目标

1. **无缝集成**：复用现有心跳保存和手动保存机制，无需新增保存逻辑
2. **最小改动**：只修改必要的 DTO 和 Controller 代码
3. **向后兼容**：不影响现有功能，PurchaseState 为可选字段
4. **统一管理**：所有角色数据通过同一管道持久化

### 2.2 修改方案

#### 2.2.1 修改 UpdateCharacterRequest DTO

**文件**: `BlazorIdle.Shared/DTOs/CharacterRequest.cs`

```csharp
public class UpdateCharacterRequest
{
    // ... 现有字段 ...

    /// <summary>
    /// 购买状态 - 追踪商店限购计数和重置时间 (Step 4)
    /// Purchase state - tracks shop purchase limits and reset times
    /// </summary>
    public BlazorIdle.Game.Purchase.PurchaseState? PurchaseState { get; set; }
}
```

#### 2.2.2 修改 CharacterController

**文件**: `BlazorIdle.Server/Controllers/CharacterController.cs`

在 `UpdateCharacter` 方法中添加：

```csharp
// 更新购买状态 (Step 4)
// Update purchase state
if (request.PurchaseState != null)
{
    character.PurchaseState = request.PurchaseState;
}
```

#### 2.2.3 修改 CharacterService

**文件**: `BlazorIdle/Services/CharacterService.cs`

在 `UpdateCharacterAsync` 方法中添加：

```csharp
var request = new UpdateCharacterRequest
{
    // ... 现有字段 ...

    // 购买状态 (Step 4)
    // Purchase state
    PurchaseState = character.PurchaseState
};
```

### 2.3 数据流图

```
游戏中购买商品
    ↓
PurchaseService.Purchase()
    ↓ 更新内存中的
PurchaseLimitTracker.IncrementCount()
    ↓
CharacterData.PurchaseState 已更新
    ↓
OnItemPurchased 回调 / 或等待定时器
    ↓
HeartbeatService.UpdateCharacter() / SaveNowAsync()
    ↓ 构建请求
CharacterService.UpdateCharacterAsync()
    ↓ 包含 PurchaseState
HTTP PUT /api/Character/{id}
    ↓
CharacterController.UpdateCharacter()
    ↓ 保存到数据库
GameDbContext.SaveChangesAsync()
    ↓
PurchaseState 持久化成功 ✅
```
