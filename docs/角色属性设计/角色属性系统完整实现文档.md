## 一、项目背景与目标

### 1.1 项目背景

原有系统仅有简单的职业模板，角色升级只改变等级数字，没有真实的属性成长。需要建立一个完整的、基于主属性成长的动态属性系统。

### 1.2 核心目标

1. **属性成长系统**: 让角色升级带来真实的数值提升
2. **职业特色**: 通过不同的主属性和权重配置体现职业风味
3. **前端计算模式**: 所有游戏逻辑在前端计算，服务器仅负责数据持久化
4. **无缝集成**: 与现有的心跳保存机制集成，确保数据安全
5. **配置驱动**: 所有职业参数通过配置文件管理，便于平衡调整

### 1.3 设计理念

- **简单明确**: 每个职业一个主属性（力量/法强/敏捷）
- **独立系统**: 耐力、急速、暴击作为独立属性
- **前端权威**: 计算在客户端完成，服务器只做存储
- **配置驱动**: 所有数值通过JSON配置文件管理

### 3.2 阶段二：属性计算核心 ✅

**时间**: 已完成  
**目标**: 实现属性派生计算逻辑

#### 实现内容

1. **计算器核心逻辑** (`AttributeCalculator.cs`)
   ```csharp
   // 主属性计算
   mainStatValue = config.BaselineMainStat + (level - 1) * config.MainStatPerLevel
   
   // 耐力计算
   stamina = config.BaselineStamina + (level - 1) * config.StaminaPerLevel
   
   // 急速/暴击计算
   haste = config.BaselineHaste + (level - 1) * config.HastePerLevel
   crit = config.BaselineCrit + (level - 1) * config.CritPerLevel
   
   // 派生属性
   damage = mainStatValue * config.MainStatToDamage
   hp = stamina * config.StaminaToHP
   
   // 应用上限
   critChance = Math.Min(crit, config.MaxCritChance)
   hasteValue = Math.Min(haste, config.MaxHaste)
   ```

2. **上限封顶逻辑**
   - 暴击率上限 60%
   - 急速上限 40%
   - 伤害最小值 1
   - HP 最小值 1

3. **DPS 计算**
   ```csharp
   baseDPS = damage / interval
   actualDPS = baseDPS * (1 + haste) * (1 + critChance * critMultiplier)
   ```

4. **输入验证** (高优先级修复)
   - 验证 level 范围 [1, 10000]
   - 验证 config 非空
   - 抛出清晰的异常消息

## 六、关键技术决策

### 6.1 前端计算模式

**决策**: 所有属性计算在前端完成

**理由**:
- 减少服务器负载
- 提高响应速度
- 便于客户端预测
- 简化服务器逻辑

**影响**:
- 需要防作弊机制（后续考虑）
- 配置文件需要可靠加载
- 计算逻辑需要高度准确

### 6.2 配置驱动设计

**决策**: 使用 JSON 配置文件管理所有职业参数

**理由**:
- 便于数值调整
- 无需重新编译
- 易于版本控制
- 支持热更新

**影响**:
- 需要配置验证机制
- 需要配置加载服务
- 需要错误处理

### 6.3 心跳保存机制

**决策**: 使用30秒心跳自动保存 + 手动保存

**理由**:
- 降低数据丢失风险
- 用户体验友好
- 服务器负载可控

**影响**:
- 需要确保数据一致性
- 需要处理并发保存
- 需要用户教育

### 6.4 独立副属性设计

**决策**: 急速和暴击不从主属性派生，独立成长

**理由**:
- 简化计算逻辑
- 提高职业差异化
- 便于平衡调整
- 为未来装备系统预留空间

**影响**:
- 配置参数增多
- 需要更多测试
- 数值平衡复杂度增加

## 八、已知问题与限制

### 8.1 高优先级 - 已全部修复 ✅

1. ✅ ~~魔术数字过多~~ - 已创建 AttributeLimits.cs
2. ✅ ~~缺少输入验证~~ - 已添加完整验证
3. ✅ ~~HeartbeatService内存泄漏风险~~ - 已验证无问题

### 8.2 中优先级 - 待后续处理 ⚠️

1. **配置验证不完善**
   - 当前仅检查配置是否存在
   - 需要验证数值合理性（如基线>0，权重>=0等）
   
2. **缺少并发保护**
   - 快速连续升级/切换职业可能有竞态条件
   - 需要添加防抖/节流机制

3. **心跳保存无重试机制**
   - 保存失败后不会重试
   - 需要添加指数退避重试

4. **缺少乐观锁**
   - `UpdateCharacterAsync` 可能有并发更新问题
   - 需要添加版本号或时间戳验证

5. **UI更新频率过高**
   - 每次属性变化都触发StateHasChanged
   - 需要优化更新频率

### 8.3 低优先级 - 可选改进 ℹ️

1. 大数值显示不够友好（如 123456 → 123K）
2. 缺少加载状态提示
3. 性能监控不完整
4. 文档需要持续完善
5. 单元测试覆盖不足
6. 错误日志级别使用不当
7. 缺少属性计算缓存
8. DPS 计算可能溢出（极高数值）

### 8.4 已知技术限制

1. **BeforeUnload 保存不可靠**
   - 浏览器安全限制
   - 异步操作可能被取消
   - 已文档化，建议用户手动保存
