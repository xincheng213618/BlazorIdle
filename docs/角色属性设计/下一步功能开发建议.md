### 4.3 技术实现要点

#### 4.3.1 资源系统设计

**核心类**：
```csharp
// BlazorIdle.Shared/Game/ResourceManager.cs
public class ResourceManager
{
    public static void UpdateResource(
        ResourceState resource, 
        double deltaTime,
        ResourceEvent? event = null)
    {
        // 1. 自然恢复
        if (resource.RegenerationRate > 0)
        {
            resource.CurrentValue += resource.RegenerationRate * deltaTime;
        }
        
        // 2. 事件生成/消耗
        if (event != null)
        {
            resource.CurrentValue += event.Amount;
        }
        
        // 3. 上限处理
        resource.CurrentValue = Math.Max(0, 
            Math.Min(resource.CurrentValue, resource.MaxValue));
    }
}
```

#### 4.3.2 Special脉冲设计

**核心逻辑**：
```csharp
// BlazorIdle.Shared/Game/SpecialPulseManager.cs
public class SpecialPulseManager
{
    private double _elapsedTime = 0;
    
    public SpecialPulseEvent? Update(
        double deltaTime, 
        ProfessionConfig config)
    {
        _elapsedTime += deltaTime;
        
        if (_elapsedTime >= config.SpecialPulseInterval)
        {
            _elapsedTime -= config.SpecialPulseInterval;
            return new SpecialPulseEvent
            {
                Type = config.PulseEffectType,
                Parameters = config.PulseParameters
            };
        }
        
        return null;
    }
}
```

#### 4.3.3 Buff系统设计

**核心逻辑**：
```csharp
// BlazorIdle.Shared/Game/BuffManager.cs
public class BuffManager
{
    private List<Buff> _activeBuffs = new();
    
    public void ApplyBuff(Buff buff)
    {
        var existing = _activeBuffs.FirstOrDefault(b => b.Id == buff.Id);
        if (existing != null)
        {
            // 刷新持续时间或叠加层数
            existing.Duration = buff.Duration;
            existing.StackCount = Math.Min(
                existing.StackCount + 1, 
                buff.MaxStacks);
        }
        else
        {
            _activeBuffs.Add(buff);
        }
    }
    
    public void UpdateBuffs(double deltaTime)
    {
        foreach (var buff in _activeBuffs.ToList())
        {
            buff.Duration -= deltaTime;
            if (buff.Duration <= 0)
            {
                _activeBuffs.Remove(buff);
            }
        }
    }
    
    public Dictionary<string, double> CalculateBuffEffects()
    {
        var totalEffects = new Dictionary<string, double>();
        foreach (var buff in _activeBuffs)
        {
            foreach (var effect in buff.Effects)
            {
                if (!totalEffects.ContainsKey(effect.Key))
                    totalEffects[effect.Key] = 0;
                    
                totalEffects[effect.Key] += effect.Value * buff.StackCount;
            }
        }
        return totalEffects;
    }
}
```

## 五、备选方案

### 5.1 方案B：直接开发技能系统

**优点**：
- 玩家体验提升最大
- 战斗玩法质变

**缺点**：

### 5.2 方案C：先完善装备系统

**优点**：
- 提供长期目标
- 增加数值成长维度

**缺点**：
- ❌ 需要Rating曲线支持
- ❌ 战斗仍然单调
- ❌ 玩家短期体验提升有限

**结论**：不推荐作为下一步，可作为后续选项

### 5.3 方案D：添加任务/成就系统

**优点**：
- 提供明确目标
- 引导玩家游戏
- 开发成本低

**缺点**：
- ⚠️ 核心玩法未改善
- ⚠️ 治标不治本

**结论**：可作为资源系统开发期间的小型功能补充

- **概率**：低

- **缓解**：资源更新频率控制，性能测试

- **影响**：高
- **缓解**：MVP设计，分步实施，充分测试

**风险3：与现有系统集成问题**
- **概率**：低
- **影响**：中
- **缓解**：增量开发，兼容性测试

### 7.2 产品风险

**风险1：玩家不喜欢新机制**
- **概率**：低
- **影响**：中
- **缓解**：参考成熟游戏设计，收集反馈

**风险2：数值平衡困难**
- **概率**：高
- **影响**：中
- **缓解**：配置化设计，易于调整

- **概率**：中

## 九、总结与建议

### 9.1 核心建议

**强烈推荐**：按照以下顺序实施

1. **第一阶段（1-2周）**：修复技术债务
   - 必要的基础工作
   - 为后续开发清除障碍
   - 成本低、收益高

2. **第二阶段（2周）**：资源/Buff/Special脉冲系统
   - **最佳的下一步选择** ⭐⭐⭐⭐⭐
   - 玩家体验提升显著
   - 技术风险可控
   - 为技能系统打基础

3. **第三阶段（2-3周）**：技能系统
   - 基于资源系统
   - 战斗玩法质变
   - 长期价值高

### 9.2 关键理由

**为什么选择资源/Buff/Special作为下一步**：

1. ✅ **时机完美**：建立在稳定的属性系统上
2. ✅ **价值最大**：显著提升玩家体验
3. ✅ **风险可控**：复杂度适中，易于测试
4. ✅ **符合规划**：按照原始roadmap顺序
5. ✅ **准备充分**：为技能系统铺路
6. ✅ **周期合理**：2周可交付MVP

### 9.3 不推荐的选项

❌ **不推荐直接开发技能系统**：
- 缺少资源系统基础
- 技能需要消耗资源
- 复杂度过高

❌ **不推荐直接开发装备词条**：
- 需要Rating曲线支持
- 核心战斗玩法仍单调
- 优先级相对较低

❌ **不推荐大规模重构**：
- 当前系统稳定良好
- 代码质量已达8.0/10
- 应增量式改进

### 9.4 执行建议

1. **先修复技术债务**（1-2周）
   - 打好基础
   - 减少后续风险

2. **实施资源/Buff/Special系统**（2周）
   - MVP优先
   - 分步交付
   - 充分测试

3. **收集反馈后规划技能系统**（2-3周）
   - 基于玩家反馈调整
   - 确保资源系统稳定
   - 设计完善后实施
