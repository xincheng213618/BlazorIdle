## 2. 阶段二：属性计算核心

### 审查范围
- `AttributeCalculator.cs`
- 属性计算公式
- DPS计算逻辑

### 发现的问题

#### ✅ 2.1 **魔术数字过多** - 已修复
**位置**: `BlazorIdle.Shared/Game/AttributeCalculator.cs`  
**问题**: 代码中硬编码了多个魔术数字
```csharp
// 问题代码示例
return Math.Max(1, (int)Math.Round(damage));  // 1是什么？
return Math.Max(0, value);  // 0是什么？
```

**影响**: 
- 代码可读性差
- 难以维护和调整
- 容易出错

**✅ 修复方案** (commit 86a6d6e):
1. 创建 `AttributeLimits.cs` 常量类，包含16个常量定义
2. 替换所有硬编码数字为命名常量
```csharp
// 新增的常量类
public static class AttributeLimits
{
    public const int MIN_LEVEL = 1;
    public const int MAX_REASONABLE_LEVEL = 10000;
    public const double MIN_STAT_VALUE = 0.0;
    public const int MIN_DAMAGE = 1;
    public const int MIN_HP = 1;
    public const double DEFAULT_MAX_CRIT_CHANCE = 0.6;
    public const double DEFAULT_MAX_HASTE = 0.4;
    // ... 更多常量
}

// 修复后的代码
return Math.Max(AttributeLimits.MIN_DAMAGE, (int)Math.Round(damage));
return Math.Max(AttributeLimits.MIN_STAT_VALUE, value);
```

**效果**: 代码可读性大幅提升，便于统一调整和维护。

#### ✅ 2.2 缺少输入验证 - 已修复
**位置**: `AttributeCalculator.Calculate()` 方法  
**问题**: 没有验证输入参数
```csharp
public static CalculatedAttributes Calculate(int level, ProfessionAttributeConfig config, ...)
{
    // 缺少验证：
    // - level 可能为负数或超大值
    // - config 可能为null
    // - equipBonuses 可能包含异常值
}
```

**✅ 修复方案** (commit 86a6d6e):
添加了全面的输入验证：
```csharp
// 验证等级范围
if (level < AttributeLimits.MIN_LEVEL)
{
    throw new ArgumentOutOfRangeException(
        nameof(level), level, 
        $"Level must be at least {AttributeLimits.MIN_LEVEL}");
}

if (level > AttributeLimits.MAX_REASONABLE_LEVEL)
{
    throw new ArgumentOutOfRangeException(
        nameof(level), level, 
        $"Level exceeds reasonable maximum of {AttributeLimits.MAX_REASONABLE_LEVEL}");
}

// 验证配置非空
if (config == null)
{
    throw new ArgumentNullException(nameof(config), "Profession config cannot be null");
}
```

**效果**: 
- 提前发现参数错误
- 提供清晰的错误消息
- 防止异常数据进入计算流程

#### ⚠️ 2.3 DPS计算可能溢出
**位置**: `CalculateTotalDPS()` 方法  
**问题**: 高等级时DPS值可能非常大，存在数值溢出风险  
**建议**: 
- 使用 `double` 而非 `float` 存储DPS
- 添加溢出检查
- 考虑使用科学计数法显示

#### ⚠️ 2.4 属性计算没有缓存
**问题**: 相同level和config的重复计算没有缓存  
**影响**: 性能浪费，尤其在批量计算时  
**建议**: 考虑添加LRU缓存
```csharp
private static readonly LRUCache<string, CalculatedAttributes> _cache 
    = new LRUCache<string, CalculatedAttributes>(capacity: 1000);

public static CalculatedAttributes Calculate(int level, ProfessionAttributeConfig config)
{
    var key = $"{config.ProfessionId}_{level}";
    if (_cache.TryGetValue(key, out var cached))
        return cached;
    
    var result = CalculateInternal(level, config);
    _cache.Add(key, result);
    return result;
}
```

#### ✅ 2.5 良好实践
- 计算逻辑清晰
- 公式实现正确
- 注释详细

## 3. 阶段三：集成触发机制

### 审查范围
- `CharacterAttributeService.cs`
- 触发点集成
- 事件系统

### 发现的问题

#### ⚠️ 3.1 缺少并发保护
**位置**: `CharacterAttributeService.RecalculateAndApplyAsync()`  
**问题**: 多线程同时调用可能导致竞态条件
```csharp
public async Task RecalculateAndApplyAsync(CharacterData character)
{
    // 如果两个线程同时调用，可能会出现问题
    var config = await _professionService.GetConfigAsync(...);
    var attrs = AttributeCalculator.Calculate(...);
    // 应用到character对象 - 这里可能被其他线程修改
}
```

**建议**: 添加锁机制或使用 `SemaphoreSlim`
```csharp
private readonly SemaphoreSlim _semaphore = new SemaphoreSlim(1, 1);

public async Task RecalculateAndApplyAsync(CharacterData character)
{
    await _semaphore.WaitAsync();
    try
    {
        // ... 计算逻辑
    }
    finally
    {
        _semaphore.Release();
    }
}
```

#### ⚠️ 3.2 事件发布可能阻塞主流程
**位置**: 事件触发点  
**问题**: 如果事件处理器执行耗时操作，会阻塞主流程  
**建议**: 使用异步事件或后台任务队列

#### ⚠️ 3.3 缺少错误重试机制
**问题**: 配置加载失败后没有重试  
**影响**: 网络抖动可能导致计算失败  
**建议**: 添加重试策略（如Polly）

#### ✅ 3.4 良好实践
- 触发点设计合理
- 与现有系统集成良好

## 4. 阶段四：持久化集成

### 审查范围
- `HeartbeatService.cs`
- `CharacterService.UpdateCharacterAsync()`

### 发现的问题

#### ✅ 4.1 **HeartbeatService内存泄漏风险** - 已验证
**位置**: `HeartbeatService.cs`  
**状态**: 经审查，现有实现已正确处理资源释放，无需修改

**现有实现**:
```csharp
public HeartbeatService(...)
{
    // 订阅事件
    _characterService.SelectedCharacterChanged += OnSelectedCharacterChanged;
}

public void Dispose()
{
    // ✅ 正确取消事件订阅
    _characterService.SelectedCharacterChanged -= OnSelectedCharacterChanged;
    
    // ✅ 停止并清理Timer
    Stop();
}
```

**验证结果**:
- ✅ Dispose()方法正确实现，会取消事件订阅
- ✅ 服务注册为Scoped生命周期（Program.cs中 `AddScoped<IHeartbeatService, HeartbeatService>()`）
- ✅ Blazor会在Scope结束时自动调用Dispose
- ✅ Timer也被正确释放
- ✅ 无内存泄漏风险

**结论**: 现有实现符合最佳实践，无需修改。

#### ⚠️ 4.2 心跳保存失败没有重试
**位置**: `HeartbeatService.SaveCharacterDataAsync()`  
**问题**: 保存失败后只记录日志，不重试  
**影响**: 网络问题可能导致数据丢失  
**建议**: 
```csharp
private async Task SaveCharacterDataAsync(CharacterData character)
{
    int retryCount = 3;
    for (int i = 0; i < retryCount; i++)
    {
        try
        {
            var result = await _characterService.UpdateCharacterAsync(...);
            if (result?.Success == true)
                return;
        }
        catch (Exception ex)
        {
            if (i == retryCount - 1)
                _logger.LogError(ex, "Failed after {RetryCount} retries", retryCount);
            else
                await Task.Delay(1000 * (i + 1)); // 指数退避
        }
    }
}
```

#### ⚠️ 4.3 UpdateCharacterAsync缺少乐观锁
**位置**: `CharacterService.UpdateCharacterAsync()`  
**问题**: 多个客户端同时修改同一角色时，可能发生数据覆盖  
**建议**: 添加版本号或时间戳检查
```csharp
public class CharacterData
{
    public long Version { get; set; }  // 版本号
    // 或
    public DateTime LastModified { get; set; }  // 最后修改时间
}
```

#### ⚠️ 4.4 BeforeUnload保存机制不可靠
**位置**: `BeforeUnloadService.cs`  
**问题**: 
- 浏览器可能取消异步操作
- 不同浏览器行为不一致
- 移动端支持差

**状态**: 已知问题，已有文档说明，建议用户依赖手动保存  
**建议**: 考虑使用Service Worker或Background Sync API

#### ✅ 4.5 良好实践
- HeartbeatService设计合理
- 手动保存功能完善
- 错误处理基本完善

## 5. 阶段五：UI展示

### 审查范围
- 属性显示组件
- UI更新机制
- 用户反馈

### 发现的问题

#### ⚠️ 5.1 UI更新频率可能过高
**位置**: 属性显示组件  
**问题**: 每次属性变化都触发UI更新，可能导致性能问题  
**建议**: 
- 使用节流（Throttle）机制
- 批量更新
- 仅更新变化的部分

```csharp
private DateTime _lastUpdate = DateTime.MinValue;
private const int UPDATE_INTERVAL_MS = 100;  // 最多100ms更新一次

private void OnAttributeChanged()
{
    var now = DateTime.Now;
    if ((now - _lastUpdate).TotalMilliseconds < UPDATE_INTERVAL_MS)
        return;
    
    _lastUpdate = now;
    StateHasChanged();
}
```

#### ⚠️ 5.2 大数值显示不友好
**问题**: 属性值很大时（如HP=123456）不易阅读  
**建议**: 
- 使用千分位分隔符：123,456
- 或使用K/M简写：123.5K
```csharp
public static string FormatLargeNumber(int value)
{
    if (value >= 1000000) return $"{value / 1000000.0:F1}M";
    if (value >= 1000) return $"{value / 1000.0:F1}K";
    return value.ToString();
}
```

#### ⚠️ 5.3 缺少加载状态提示
**问题**: 属性计算时没有加载指示器  
**影响**: 用户可能不知道系统正在计算  
**建议**: 添加loading spinner或骨架屏

#### ✅ 5.4 良好实践
- UI组件结构清晰
- 属性格式化合理
