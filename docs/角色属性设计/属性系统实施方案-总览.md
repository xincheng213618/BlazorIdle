# 角色属性系统实施方案 - 总览

## 文档目的

本文档提供角色属性系统的完整实施方案，将原有的简单职业模板升级为基于主属性成长的动态属性系统。实施将分为多个阶段，每个阶段都有明确的目标、任务清单和验证标准。

## 系统目标

1. **属性成长系统**：让角色升级带来真实的数值提升，而不仅仅是等级数字变化
2. **职业特色**：通过不同的主属性和权重配置体现职业风味
3. **前端计算模式**：所有游戏逻辑在前端计算，服务器仅负责数据持久化
4. **无缝集成**：与现有的心跳保存机制集成，确保数据安全
5. **配置驱动**：所有职业参数通过配置文件管理，便于平衡调整

## 架构设计

### 计算模型

```
配置层 (Server/Config/)
  ↓
加载层 (GameConfigController API)
  ↓
前端计算层 (Shared/Game/)
  ↓
应用层 (Client Services)
  ↓
持久化层 (Heartbeat + Manual Save)
```

### 核心概念

- **主属性 (MainStat)**：每个职业一个核心属性（力量/法强/敏捷），仅影响伤害
- **耐力属性 (Stamina)**：独立属性，影响角色生命值
- **独立副属性**：急速(Haste)和暴击(Crit)作为独立属性，不从主属性派生
- **职业基线 (Baseline)**：职业的基础属性值
- **成长权重 (Weights)**：各属性的转换系数

## 实施阶段划分

### 阶段一：配置基础设施（1-2天）
**目标**：建立配置文件结构和加载机制

- 创建职业属性配置文件
- 实现配置加载API
- 创建配置模型类
- 编写配置验证逻辑

### 阶段二：属性计算核心（2-3天）
**目标**：实现属性派生计算逻辑

- 实现主属性计算
- 实现派生属性计算
- 实现上限封顶逻辑
- 创建计算工具类

### 阶段三：集成触发机制（1-2天）
**目标**：在正确的时机触发属性重算

- 加载时计算
- 升级时计算
- 切换职业时计算
- 更新CharacterData

### 阶段四：持久化集成（1天）
**目标**：与心跳机制集成，确保数据保存

- 验证心跳自动保存
- 实现特定动作保存（切换、退出）
- 添加手动保存按钮
- 测试持久化流程

### 阶段五：UI展示（半天）
**目标**：更新现有CharacterDetail组件以显示新属性

- 更新CharacterDetail组件
- 显示主属性、耐力、急速、暴击等级
- 实现属性实时更新
- 可选的属性变化提示

### 阶段六：测试与调优（2-3天）
**目标**：验证系统正确性和平衡性

- 功能测试
- 数值校准
- 性能测试
- 边界测试

## 总工时估算

- **最小工时**：30-31小时（约4-5个工作日）
- **预期工时**：8-10个工作日
- **含缓冲**：12个工作日

## 关键风险与对策

### 风险1：现有战斗系统不兼容
**对策**：使用兼容模式，先写入现有字段结构

### 风险2：配置参数不平衡
**对策**：预留调参阶段，提供快速配置热更新

### 风险3：持久化数据丢失
**对策**：多层保存机制（心跳+事件+手动）

### 风险4：前端性能问题
**对策**：计算逻辑简单高效，缓存计算结果

## 验收标准

1. ✅ 升级后属性值有明显提升
2. ✅ 不同职业在同级有不同的属性表现
3. ✅ 属性在切换职业时正确切换
4. ✅ 属性变化能够持久化保存
5. ✅ UI正确显示所有关键属性
6. ✅ 不存在属性计算错误或异常值
7. ✅ 与现有战斗系统完全兼容
