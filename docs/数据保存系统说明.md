# BlazorIdle 数据保存系统说明

## 概述

BlazorIdle 使用多层数据保存机制来确保玩家数据的安全性和可靠性。本文档详细说明了当前实现的保存机制、已知问题和最佳实践。

## 数据保存机制

### 1. 心跳自动保存 ✅ **正常工作**

**触发时机**: 每隔一定时间间隔（默认配置）自动保存

**实现位置**:
- `BlazorIdle/Services/HeartbeatService.cs`
- `BlazorIdle/Configuration/HeartbeatConfiguration.cs`

**工作原理**:
1. 当玩家选择角色后，HeartbeatService 自动启动
2. 定时器按照配置的间隔触发保存操作
3. 通过 `UpdateCharacterAsync` 方法将角色数据发送到服务器
4. 包含所有属性：战斗属性、库存数据、职业数据等

**数据更新流程**:
```
Home.razor (游戏进行中)
  ↓ OnCharacterDataChanged 回调
  ↓ HeartbeatService.UpdateCharacter()
  ↓ 更新内存中的角色数据引用
  ↓ 定时器触发
  ↓ CharacterService.UpdateCharacterAsync()
  ↓ 发送 HTTP PUT 请求到服务器
  ↓ 服务器保存到数据库
```

**优点**:
- 自动化，无需玩家操作
- 可靠性高，经过充分测试
- 数据实时更新，保存的是最新状态

**配置**:
可在 `HeartbeatConfiguration` 中调整保存间隔。

---

### 2. 手动保存 ✅ **正常工作**

**触发时机**: 玩家点击界面右上角的"保存"按钮

**实现位置**:
- `BlazorIdle/Components/SaveButton.razor`
- UI 位置：UserBar 组件中

**工作原理**:
1. SaveButton 调用 `HeartbeatService.SaveNowAsync()`
2. HeartbeatService 立即保存当前跟踪的角色数据
3. 包含冷却时间机制（10秒），防止频繁点击

**数据流程**:
```
SaveButton.OnSaveClicked()
  ↓ 检查 HeartbeatService.IsRunning
  ↓ HeartbeatService.SaveNowAsync()
  ↓ CharacterService.UpdateCharacterAsync()
  ↓ 服务器保存数据
  ↓ 显示保存成功/失败状态
```

**优点**:
- 玩家可控，在重要操作后主动保存
- 提供即时反馈
- 有冷却保护，避免服务器压力

**使用建议**:
- 在获得重要物品后手动保存
- 升级后手动保存
- 进行重要操作前后手动保存
- 离开游戏前手动保存

---

### 3. 页面关闭自动保存 ⚠️ **已知问题**

**触发时机**: 页面刷新、关闭标签页、关闭浏览器、退出登录时

**实现位置**:
- `BlazorIdle/Services/BeforeUnloadService.cs`
- `BlazorIdle/wwwroot/js/beforeUnload.js`
- `BlazorIdle/Layout/MainLayout.razor`

**当前状态**: ⚠️ **不稳定，不建议依赖**

#### 已知问题

**问题描述**:
页面关闭时的自动保存可能无法可靠触发，服务器端可能收不到保存请求。

**技术原因**:
1. **浏览器限制**: `beforeunload` 事件中的异步操作可能被浏览器取消
2. **时序问题**: 页面卸载时 JavaScript 和 .NET 运行时可能已经停止
3. **网络请求限制**: 浏览器在页面卸载时会中断未完成的 HTTP 请求
4. **跨浏览器兼容性**: 不同浏览器对页面卸载事件的处理差异较大

**尝试的解决方案**:
- ✅ 添加 `pagehide` 事件监听（移动端更可靠）
- ✅ 添加 `visibilitychange` 事件监听
- ✅ 使用 HeartbeatService 确保保存最新数据
- ✅ 添加详细日志用于调试
- ❌ 仍然不能保证 100% 可靠

**为什么难以完全解决**:
现代浏览器为了安全性和性能，严格限制页面卸载时的操作：
- 异步操作（如 HTTP 请求）可能被立即取消
- JavaScript 执行可能被中断
- Blazor WebAssembly 运行时可能已经停止
- 即使使用 `sendBeacon` API 也无法保证在 Blazor WASM 环境中可靠工作

#### 调试方法

如果想验证此功能，可以检查浏览器控制台（F12）：

**页面加载时应看到**:
```
Page unload handlers registered (beforeunload, pagehide, visibilitychange)
```

**页面关闭时应看到**:
```
beforeunload event fired / pagehide event fired / visibilitychange to hidden
Triggering save before page unload
=== BeforeUnload triggered - attempting to save character ===
HeartbeatService is running, triggering save
```

**如果看到**:
```
HeartbeatService NOT running - cannot save!
```
说明 HeartbeatService 未启动（可能未选择角色或不在 Home 页面）。

## 最佳实践建议

### 🎯 推荐的数据保存策略

1. **依赖自动保存**: 正常游戏过程中，心跳自动保存会定期保存数据
2. **重要操作后手动保存**: 在以下情况主动点击保存按钮：
   - 获得稀有物品
   - 角色升级
   - 完成重要成就
   - 长时间挂机后
   - **离开游戏前**（最重要！）

3. **不要依赖页面关闭保存**: 由于浏览器限制，此功能不够可靠

### ⚠️ 风险提示

**高风险操作**:
- 直接关闭浏览器/标签页而不手动保存
- 在浏览器崩溃/死机时
- 网络连接不稳定时

**建议**:
- 养成定期手动保存的习惯
- 离开游戏前务必点击保存按钮
- 观察保存按钮的反馈（显示"已保存"）

## 技术实现细节

### 数据流向

```
游戏界面（Home.razor）
  ↓
角色数据更新（战斗、升级等）
  ↓
OnCharacterDataChanged 事件
  ↓
HeartbeatService.UpdateCharacter()
  ↓
内存中的角色数据引用更新
  ↓
[定时器触发] 或 [手动保存触发]
  ↓
HeartbeatService.SaveNowAsync()
  ↓
CharacterService.UpdateCharacterAsync()
  ↓
HTTP PUT 请求到 API 服务器
  ↓
服务器端数据库更新
```

### 保存的数据内容

通过 `UpdateCharacterRequest` 发送到服务器的数据包括：

**角色属性**:
- MaxHp (最大生命值)
- AttackRateAPS (攻击速度)
- DamagePerAttack (每次攻击伤害)
- HastePercent (急速百分比)
- SpecialIntervalSec (技能间隔)
- SpecialDamage (技能伤害)
- CritChancePercent (暴击率)
- CritMultiplier (暴击倍率)
- VariancePct (伤害浮动)
- ReviveSec (复活时间)

**库存数据**:
- Inventory (完整的物品清单)

**职业数据**:
- Professions (所有职业的等级和经验)
- ActiveCombatProfessionId (当前激活的战斗职业)

## 故障排查

### 问题：心跳保存不工作

**检查项**:
1. 是否选择了角色？
2. 是否在 Home 页面？
3. 检查浏览器控制台是否有错误
4. 检查网络请求是否成功（F12 → Network）

### 问题：手动保存按钮无响应

**检查项**:
1. 是否在冷却期内（10秒）？
2. 按钮是否显示"保存中"？
3. 是否选择了角色？
4. 检查浏览器控制台是否有"HeartbeatService NOT running"

### 问题：数据丢失

**可能原因**:
1. 最后一次游戏后没有手动保存
2. 直接关闭浏览器/标签页
3. 浏览器崩溃
4. 网络连接中断时保存失败

**预防措施**:
- 养成离开前手动保存的习惯
- 重要操作后立即保存
- 确保网络连接稳定

## 总结

BlazorIdle 目前拥有**可靠的心跳自动保存**和**手动保存**机制，这两种方式已经过充分测试，可以放心使用。

⚠️ **重要提醒**: 由于浏览器技术限制，**页面关闭自动保存不够可靠**，请务必在离开游戏前**点击保存按钮**进行手动保存！
