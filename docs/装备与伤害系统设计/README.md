# 设计文档索引（5 文件方案）

版本：v1.0  
日期：2025-11-29  
作者：@copilot

本仓库采用 5 文件方案管理装备与战斗数值设计。每个文件职责清晰、相互引用，支持后续独立迭代与调参。

- affixes_initial_design.md（v1.4）
- Step6_伤害组成与计算管线_详细设计.md（v1.2）

--------------------------------
文件职责与依赖关系
--------------------------------
1) Step5_装备系统_详细设计_GBF式装备栏.md  
- 职责：定义装备栏结构（主手 + 9 副槽）、主手职业武器类型限制、主手决定角色元素、与词条/强化/伤害系统的高层接口。  
- 关键点：同一件装备可放主手或副槽；仅主手受职业限制并决定角色元素。  
- 依赖：
  - 引用 Step5_装备词条系统 以说明装备属性来源（Attack%、HP%、Crit 等字段）。
  - 引用 Step5_装备强化与分解系统 以说明装备获取、强化与分解流程。
  - 引用 Step6 伤害管线以说明元素与属性在战斗中的作用。

2) Step5_装备强化与分解系统_详细设计更新_v1.3.md  
- 职责：统一“仅通用材料强化”的成本模型、分层材料（Tier）、自动/批量分解、分解返还强化材料（全额回退）。  
- 关键点：强化 +3 同步提升装备内所有词条等级；分解返还全部强化投入材料（不含基础分解收益）。  
- 依赖：
  - 引用 Step5_装备系统（槽位与装备品质裁剪）与 Step5_词条系统（词条等级与成长曲线）。
  - 活动和掉落可参考独立配置，不在本文件内。

3) Step5_装备词条系统_详细设计.md（v2.1）  
- 职责：词条框架、分类与上限（Caps）、双攻击系（Attack% / SpecialAttack%）、HP%、暴击基础倍率与加成、态势（盛体/背水互斥）、追击（百分比/克制/固定）、互斥与限量规则、等级成长（Lv1 最大递减）。  
- 关键点：固定词条序列（橙品质完整，低品质截取前 N 条）；仅百分比化（固定追击除外）；强化同步升级不引入额外乘区。  
- 依赖：
  - 与 Step6 伤害管线字段对齐（AttackPct、SpecialAttackPct、CritChancePct、CritDamageBonusPct、Fortify/Backwater、Chase/KenChase、HPPercent、DamageReduction%）。
  - 具体数值在 affixes_initial_design.md 中维护。

4) affixes_initial_design.md（v1.4）  
- 职责：初期词条的具体数值与 JSON 示例（Lv1→Lv4，Lv1收益最大）；包括 attack、special_attack、hp、crit、crit_damage_bonus、assault、fortify_boost、backwater_boost、chase_pct、chase_flat、ken_chase、mitigation、element_resonance 等。  
- 关键点：确保 10 件满配 Lv4 堆叠不越过 Caps；通过互斥/限量规则控制构筑安全。  
- 依赖：
  - 设计规范与字段由 Step5_装备词条系统提供；  
  - 在实现时由 Step6 伤害管线读取并参与计算。

5) Step6_伤害组成与计算管线_详细设计.md（v1.2）  
- 职责：定义伤害计算层级与公式（基础→主体→暴击→元素→追击→减伤→收尾）、态势互斥映射、伪代码与测试矩阵。  
- 关键点：主体乘区 = (1+Attack%)×(1+SpecialAttack%)×(1+Stance%)；暴击基础倍率 1.2 + 额外暴击伤害%；元素层独立；追击在尾部加法；固定追击受减伤。  
- 依赖：
  - 从 Step5_装备词条系统与 affixes_initial_design 读取属性字段与上限；
  - 与 Step5_装备系统的元素与职业限制逻辑对齐。

--------------------------------
版本约定与更新策略
--------------------------------
- 版本号格式：vMajor.Minor，日期置顶。  
- 框架与规则（Step5_词条系统、Step6_伤害管线）尽量保持稳定；数值与掉落（affixes_initial_design、强化材料 X 值）按需求迭代。  
- 任何字段名或 Caps 变更必须同时更新：Step5_词条系统、Step6 伤害管线、affixes_initial_design。  
- 强化/分解成本与材料分级的调参仅在强化与分解系统文件内修改，并于 README 更新要点。

--------------------------------
落地顺序（建议）
--------------------------------
1. 优先完成 Step6 伤害管线基础实现（含 Caps 与态势互斥映射）。  
2. 接入 Step5_装备词条系统字段，跑单元测试（裁剪、互斥、限量）。  
3. 应用 affixes_initial_design 的初始数值；实现强化 +3 与分解回退（参考强化/分解系统）。  
4. 完成主手元素与职业限制（装备系统），连接至战斗。  
5. 增加自动分解与战前掉落预览 UI，完善日志与分析面板。

--------------------------------
维护约定
--------------------------------
- 每个文件置顶“版本/日期/作者/更新摘要”四项元信息。  
- 变更需在 README“版本约定与更新策略”中列出要点。  
- 历史版本移入 /archive/ 目录，文件名附版本与日期。  
- 定期运行数值校验脚本：随机 10 件橙装 Lv4 → 汇总属性 → 检查 Caps、互斥、equipLimit。
