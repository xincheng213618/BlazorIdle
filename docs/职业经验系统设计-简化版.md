# 职业与经验系统设计 - 简化实现版

## 设计原则

基于用户反馈的简化设计，专注于核心战斗职业系统，保留未来扩展接口。

## 一、核心概念

### 1.1 职业体系

**战斗职业 (Combat Professions)**
- 战士 (Warrior)
- 法师 (Mage)  
- 游侠 (Ranger)
- （可扩展更多）

**非战斗职业 (Non-Combat Professions)**
- 采矿 (Mining)
- 草药学 (Herbalism)
- 锻造 (Blacksmithing)
- 炼金 (Alchemy)
- （可扩展更多）

**关键特性**
- 每个角色**同时拥有所有职业**
- 每个职业独立追踪等级和经验
- 战斗前可切换激活的战斗职业
- 非战斗职业暂不实现动作系统，只保留数据结构

### 1.2 经验获取

**战斗经验**
- 来源：击败怪物、通关副本
- 配置位置：
  - `monsters.json` - 每个怪物的 `baseExperience` 字段
  - `dungeons.json` - 副本的 `completionExperience` 字段
- 计算公式：`实际经验 = 基础经验 × (1 + 增益系数)`
- 增益系数：默认为0，预留给未来buff系统
- 分配规则：经验只给当前激活的战斗职业

**TODO - 未来扩展**
- 等级差系数（高等级打低等级怪经验惩罚）
- 组队经验分配
- 经验加成道具/buff

**非战斗经验**
- 暂不实现，预留接口
- 未来通过采集、制作等动作获取

### 1.3 升级机制

**简化原则**
- ✅ 升级增加等级数字
- ❌ 升级**不增加**属性
- ❌ 升级**不解锁**技能（改为需求检查）

**战斗职业升级效果**
- Level +1
- 经验重置（保留溢出）
- 更新升级所需经验（查表）
- 触发升级事件（UI显示）

**非战斗职业升级效果**
- Level +1  
- 解锁更高级的采集点（未来实现）
- 解锁更高级的配方（未来实现）
- 不提供任何增益效果

## 三、核心功能实现

### 3.1 角色创建流程

```
用户输入角色名 
  → 后端创建角色（默认warrior为激活职业）
  → 初始化所有职业进度（全部Level 1, Exp 0）
  → 根据warrior职业设置角色战斗属性
  → 返回完整角色数据
```

**UI变化**
- ❌ 移除职业选择下拉框
- ✅ 添加提示信息："角色将拥有所有职业，默认为战士"

### 3.2 职业切换流程

**前置条件**
- 角色不在战斗中
- 角色不在活动中
- 目标职业为战斗职业

**API接口**
```
POST /api/character/{id}/switch-profession
Body: { "professionId": "mage" }

响应：
- 更新 ActiveCombatProfessionId
- 根据新职业的ProfessionDef更新角色战斗属性
- 返回更新后的角色数据
```

**重要说明**
- 属性直接使用职业基础属性
- **不考虑等级成长**（简化实现）
- 未来如需等级成长，在此处添加计算逻辑

### 3.3 战斗经验获取

**触发时机**：怪物死亡后

**流程**
```
1. 获取怪物的 baseExperience
2. 应用增益系数：actualExp = baseExperience × (1 + multiplier)
   - TODO: multiplier 暂时为 0，未来从 buff 系统获取
3. 将经验添加到 character.Professions[ActiveCombatProfessionId]
4. 检查是否升级
5. 生成经验获得事件（UI显示）
```

**BattleInstance 集成**
```csharp
// 在 ProcessLootDrops() 之后调用
private void ProcessExperienceGain(int now)
{
    if (_enemy.BaseExperience <= 0) return;
    
    // TODO: 获取增益系数
    double multiplier = 0.0; // 预留给未来buff系统
    
    long actualExp = (long)(_enemy.BaseExperience * (1.0 + multiplier));
    
    // 触发经验事件
    ExperienceGained?.Invoke(new ExperienceGainEvent
    {
        TimeMs = now,
        ProfessionId = _player.ActiveCombatProfessionId,
        Experience = actualExp
    });
}
```

### 3.4 副本完成经验

**触发时机**：副本通关时

**流程**
```
1. 获取副本的 completionExperience
2. 应用增益系数（同上）
3. 分配给当前激活的战斗职业
4. 触发经验事件
```

### 3.5 升级逻辑

**检查条件**：`progress.Experience >= progress.ExperienceToNext`

**执行步骤**
```csharp
public void ProcessLevelUp(ProfessionProgress progress)
{
    // 1. 增加等级
    progress.Level++;
    
    // 2. 扣除经验，保留溢出
    progress.Experience -= progress.ExperienceToNext;
    
    // 3. 查表更新下一级所需经验
    progress.ExperienceToNext = GetExperienceRequired(progress.Level + 1);
    
    // 4. 触发升级事件
    LevelUpOccurred?.Invoke(new LevelUpEvent
    {
        ProfessionId = progress.ProfessionId,
        NewLevel = progress.Level
    });
    
    // 注意：不更新角色属性（简化设计）
}
```

**重要**
- ❌ 不调用属性增长函数
- ❌ 不解锁技能
- ✅ 只更新数字和触发事件

## 九、注意事项

### 9.1 数据一致性
- 所有经验修改必须经过服务器验证
- 客户端只显示，不计算经验
- 使用乐观锁防止并发问题

### 9.2 性能考虑
- 职业数据随角色一起加载，无需单独查询
- 经验曲线配置全局缓存
- 避免频繁的数据库写入（批量/心跳）

### 9.3 用户体验
- 切换职业时显示属性变化对比
- 经验获得即时反馈
- 升级特效吸引注意力
- 清晰的进度条显示

### 9.4 安全性
- 验证职业类型（只能切换到战斗职业）
- 验证角色拥有该职业
- 防止经验值溢出（使用 long 类型）
- 经验增益系数有上限（防止异常buff）
