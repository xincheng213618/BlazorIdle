# 角色数据心跳保存功能说明
# Character Data Heartbeat Save Feature Documentation

## 概述 (Overview)

本功能实现了角色数据的自动定时保存（心跳保存）机制，确保用户的游戏进度能够定期自动保存到服务器，防止数据丢失。

This feature implements an automatic periodic save (heartbeat save) mechanism for character data, ensuring that user game progress is regularly saved to the server automatically, preventing data loss.

## 功能特性 (Features)

### 1. 自动定时保存 (Automatic Periodic Save)
- 系统会自动每隔一段时间（默认30秒）保存当前选中角色的数据
- 保存内容包括角色的所有属性和库存信息
- 无需手动操作，完全自动化

The system automatically saves the currently selected character's data at regular intervals (default: 30 seconds).
Saved data includes all character attributes and inventory information.
No manual operation required, fully automated.

### 2. 智能角色切换 (Smart Character Switching)
- 当用户切换角色时，系统会自动停止旧角色的心跳保存
- 并立即为新选中的角色启动心跳保存
- 用户无需关心心跳服务的管理

When users switch characters, the system automatically stops the heartbeat save for the old character and immediately starts it for the newly selected character.
Users don't need to worry about managing the heartbeat service.

### 3. 完全可配置 (Fully Configurable)
- 所有参数都可以通过配置文件进行调整
- 包括保存间隔时间和是否启用自动保存
- 无需修改代码，方便运维管理

All parameters can be adjusted through configuration files.
Includes save interval time and whether to enable auto-save.
No code modification required, convenient for operations management.

### 4. 可扩展设计 (Extensible Design)
- 更新接口支持部分更新，只更新有变化的字段
- 便于未来添加新的角色属性
- 不影响现有功能

The update interface supports partial updates, only updating changed fields.
Easy to add new character attributes in the future.
Does not affect existing functionality.

## 配置说明 (Configuration)

### 客户端配置 (Client Configuration)
文件位置 (File location): `BlazorIdle/wwwroot/appsettings.json`

```json
{
  "HeartbeatConfig": {
    "saveIntervalSeconds": 30,
    "enableAutoSave": true
  }
}
```

### 服务器端配置 (Server Configuration)
文件位置 (File location): `BlazorIdle.Server/appsettings.json`

```json
{
  "HeartbeatConfig": {
    "saveIntervalSeconds": 30,
    "enableAutoSave": true
  }
}
```

### 配置参数说明 (Configuration Parameters)

| 参数名 (Parameter) | 类型 (Type) | 默认值 (Default) | 说明 (Description) |
|-------------------|------------|-----------------|-------------------|
| saveIntervalSeconds | int | 30 | 自动保存间隔时间（秒）<br>Auto-save interval (seconds) |
| enableAutoSave | bool | true | 是否启用自动保存<br>Whether to enable auto-save |

### 配置示例 (Configuration Examples)

#### 示例 1: 每分钟保存一次 (Save every minute)
```json
{
  "HeartbeatConfig": {
    "saveIntervalSeconds": 60,
    "enableAutoSave": true
  }
}
```

#### 示例 2: 禁用自动保存 (Disable auto-save)
```json
{
  "HeartbeatConfig": {
    "saveIntervalSeconds": 30,
    "enableAutoSave": false
  }
}
```

#### 示例 3: 快速保存（测试用）(Fast save for testing)
```json
{
  "HeartbeatConfig": {

    "enableAutoSave": true
  }
}
```

## 技术实现 (Technical Implementation)

### 核心组件 (Core Components)

1. **HeartbeatConfiguration** - 心跳配置类
   - 管理保存间隔和启用状态
   - 提供配置验证和默认值

2. **HeartbeatService** - 心跳服务
   - 实现定时保存逻辑
   - 使用 System.Timers.Timer 进行定时触发
   - 自动订阅角色切换事件
   - 完善的异常处理和日志记录

3. **CharacterController.UpdateCharacter** - 服务器端更新 API
   - 端点: `PUT /api/character/{id}`
   - 支持部分更新模式
   - 完整的权限验证

4. **CharacterService.UpdateCharacterAsync** - 客户端更新方法
   - 调用服务器 API 保存角色数据
   - 处理网络错误和响应

### 数据流程 (Data Flow)

```
1. 用户选择角色
   ↓
2. HeartbeatService 自动启动
   ↓
3. Timer 每隔 N 秒触发一次
   ↓
4. 调用 CharacterService.UpdateCharacterAsync()
   ↓
5. HTTP PUT 请求发送到服务器
   ↓
6. CharacterController 验证权限并更新数据库
   ↓
7. 返回成功/失败响应
   ↓
8. HeartbeatService 记录日志
```

## 使用场景 (Use Cases)

### 场景 1: 正常游戏过程 (Normal Gameplay)
1. 用户登录并选择角色
2. 心跳服务自动启动
3. 用户进行游戏（战斗、获取物品等）
4. 每30秒自动保存进度
5. 用户可以放心游戏，不用担心数据丢失

### 场景 2: 切换角色 (Switch Characters)
1. 用户当前使用角色A
2. 切换到角色B
3. 系统自动停止角色A的心跳
4. 系统自动启动角色B的心跳
5. 两个角色的数据都得到保护

### 场景 3: 网络中断恢复 (Network Interruption Recovery)
1. 网络临时中断
2. 心跳保存失败并记录日志
3. 网络恢复
4. 下一次心跳自动保存最新数据
5. 用户数据得到同步

## 故障排查 (Troubleshooting)

### 问题 1: 数据没有保存
**可能原因:**
- 心跳服务未启动
- 配置中禁用了自动保存
- 网络连接问题
- 服务器错误

**解决方法:**
1. 检查配置文件中 `enableAutoSave` 是否为 `true`
2. 查看浏览器控制台日志
3. 查看服务器日志
4. 检查网络连接

### 问题 2: 保存太频繁
**可能原因:**
- 保存间隔设置太短

**解决方法:**
1. 调整配置文件中的 `saveIntervalSeconds` 参数
2. 建议值在 30-60 秒之间

### 问题 3: 性能问题
**可能原因:**
- 保存间隔太短
- 角色数据过大

**解决方法:**
1. 增加保存间隔时间
2. 优化角色数据结构
3. 检查数据库性能

## 日志说明 (Logging)

心跳服务会记录以下日志：

### 信息级别 (Information Level)
- 心跳服务启动: "Heartbeat service started for character..."
- 心跳服务停止: "Heartbeat service stopped for character..."
- 角色数据更新成功: "User {UserId} updated character..."

### 调试级别 (Debug Level)
- 开始保存: "Heartbeat: Saving character..."
- 保存成功: "Heartbeat: Successfully saved character..."

### 警告级别 (Warning Level)
- 保存失败: "Heartbeat: Failed to save character..."
- 配置问题: "Heartbeat auto-save is disabled in configuration"

### 错误级别 (Error Level)
- 未处理的异常: "Heartbeat: Error saving character..."
- 顶层异常: "Unhandled exception in heartbeat timer elapsed handler"

## 最佳实践 (Best Practices)

1. **合理设置保存间隔**
   - 生产环境建议 30-60 秒
   - 开发测试可以设置更短（如 10 秒）

2. **监控日志**
   - 定期检查心跳服务日志
   - 及时发现和处理异常

3. **备份策略**
   - 心跳保存是增量保存
   - 仍需要定期完整备份数据库

4. **性能监控**
   - 监控数据库写入频率
   - 根据实际负载调整保存间隔

5. **测试**
   - 在生产环境部署前充分测试
   - 验证各种场景下的数据完整性
