1. 背景与目标
--------------------------------
- 在现有技能系统（Step2/Step3）基础上提供“技能商店”，让玩家通过消耗货币来直接学习技能或购买技能书，以实现玩法横向拓展。
- 采用最小可行（MVP）方案：不做动态价格，不做刷新/轮换；保留可扩展接口，未来自然演进为装备商店、挑战商店等。
- 与已有模块深度集成：SkillLearningManager（学习技能）、ResourceManager（货币扣除）、Inventory（技能书与道具管理）。

目标：
- 实现一个“技能商店”类型，涵盖商品展示、折扣定价、解锁条件、限购、购买与效果应用、UI 展示与基本测试。
- 提供清晰的数据结构与流程，确保后续扩展“装备商店/挑战商店”时无需大改。

--------------------------------
2. 范围与非目标
--------------------------------
范围（本期实现）：
- 商店类型：skill（技能商店）
- 商品效果：两类
  - learn_skill：购买后直接学习技能
  - grant_item：购买后发放技能书（可在背包中使用以学习技能）
- 定价：固定价格 + 折扣（店铺级 + 商品级），不含动态浮动
- 限购：每日/账号/角色 三类并列
- 解锁：职业、等级、账户/事件 Flag、必须使用过某道具、必须已掌握某技能（前置）
- 单机前端权威（无服务端校验），本地持久化状态
- UI：技能商店基础面板 + 背包中使用技能书

非目标（后续阶段实现）：
- 商店刷新（定时/手动）与随机轮换池
- 动态定价、活动价、VIP 折扣
- 装备商店 / 挑战商店 / 黑市
- 服务器权威验证、防刷、安全审计

--------------------------------
3. 约束与设计原则
--------------------------------
- 简洁：为放置玩法设计，拒绝过度复杂化；以配置驱动为主。
- 可扩展：所有可选能力预留配置与接口（如 RefreshPolicy、动态定价占位）。
- 一致性：与现有 Step2/Step3 事件、资源、技能学习风格一致。
- 原子性：购买流程按原子顺序执行（扣货币→应用效果→更新限购）；失败则回滚。
- 可测试：每个规则有可验证的单元/集成测试。
- 可观测：提供基础事件与调试日志（Debug 模式）。

--------------------------------
4. 名词与角色
--------------------------------
- 商店（Shop/Store）：一组可购买商品的展示与购买入口，本期仅“技能商店”。
- 商品（ShopItem）：可购买的单位，绑定价格、折扣、限购与解锁条件。
- 技能书（Skill Book）：一种可使用物品，使用后学习指定技能，并可设置账户 Flag。
- 限购计数（Purchase Counters）：记录账号/角色/每日的购买次数。
- 解锁条件（Unlock Conditions）：购买前置要求（职业、等级、Flag、道具使用、前置技能等）。

--------------------------------
5. 关键用例与用户故事
--------------------------------
- 作为战士，我打开技能商店，看到“撕裂（直接学习）”，满足职业和等级后，花费金币直接学习。
- 作为法师，我购买“炎爆术技能书”，物品进入背包，我使用该书后学会炎爆术，同时账户被打上“used_mage_pyroblast_book”Flag，解锁下一级商品“奥术冲击（需已用技能书）”。
- 作为同一账号的两个角色，每个角色对某商品有独立的“角色限购”，且公用“账号限购”；次日“每日限购”自动重置。
- 我对某商品折扣为店铺 10% + 商品 20%，系统按顺序叠加并四舍五入到“整数货币”。

6. 业务规则（定价、折扣、限购、解锁）
--------------------------------
6.1 定价与折扣
- 支持货币类型：Gold、Gem、Token（可扩）
- 商品仅绑定一种货币（本期简化）
- 折扣叠加顺序：
  1) 店铺级折扣 globalDiscountPct
  2) 商品级折扣 discountFixedPct
- 折扣合并方式：线性相加后限幅（建议上限 90%），最终价 = ceil(basePrice × (1 - totalDiscount%))
- 取整规则：向上取整（保证扣费足额）

6.2 限购规则
- 三类并列：perDay / perAccount / perCharacter
- 任意一类达到上限 → 商品视为“售罄”（对该主体）
- 每日重置：以本地自然日（DateOnly）为准，进入新日清空“每日计数”；账号与角色计数不清空
- 并发：单机顺序执行，计数更新在购买成功后

6.3 解锁条件
- allowedProfessions：职业白名单
- minLevel：最低等级
- requireAccountFlags：必须具备的账户标记（成就/事件）
- requireEventFlags：预留，与账户旗标等价，命名区分来源
- requireItemUsed：[itemId...]：角色曾使用过指定道具（如某技能书）
- requireLearnedSkills：[skillId...]：已掌握前置技能
- message：UI 友好提示
- 判定顺序：职业→等级→Flag→道具使用→前置技能；任意失败返回第一条失败原因

8. 服务接口与流程
--------------------------------
8.1 接口适配（与现有系统）
- ISkillLearningApi
  - IsLearned(charId, skillId): bool
  - TryLearn(charId, skillId): (Success: bool, Message?: string)
- IResourceApi
  - GetBucketAmount(charId, currencyType): int
  - Consume(charId, currencyType, amount): void
  - Gain(charId, currencyType, amount): void（用于失败回滚）
- IInventoryApi
  - AddItem(charId, itemId, qty): void
  - ConsumeItem(charId, itemId, qty): bool（使用物品时）
- IClock
  - Now(): DateTime（每日重置）

8.2 主要流程
- 获取视图 GetShopView(storeId, characterId, professionId, characterLevel)
  1) EnsureDailyReset(storeId) → 新日清空 PerDayCounts
  2) 对每个商品：
     - 计算价格：CalcPrice（店铺折扣→商品折扣→限幅→ceil）
     - 解锁判断：CheckUnlock
     - 限购剩余：GetRemaining（day/account/char）
     - 可负担：FinalPrice ≤ 货币余额
     - 已学习（learn_skill）：IsLearned
  3) 返回 ShopView（每项包含 Label/Icon/价格/限购/可购买状态/锁定原因）

- 购买 Purchase(storeId, itemId, characterId, professionId, characterLevel)
  1) EnsureDailyReset
  2) 可见性、解锁判断、限购剩余校验、余额校验
  3) 先扣费 Consume；失败即返回（余额已校验，正常不会失败）
  4) 应用效果：
     - learn_skill：TryLearn 成功 → 继续；失败 → 返还费用 Gain → 返回 LEARN_FAIL
     - grant_item：AddItem(skill_book, qty)
  5) 更新限购计数（账号/角色/每日）
  6) 返回 OK（Spent=FinalPrice）

- 使用技能书（背包）
  1) ConsumeItem(bookId, 1) 成功 → 检查 grantsSkillId → TryLearn
  2) 若 item 配置了 onUseSetAccountFlags → 写入 AccountFlags
  3) 将 bookId 记录进 ItemsUsedByCharacter[charId]，用于“requireItemUsed”

8.3 价格计算（伪码）
```csharp
int CalcFinalPrice(int basePrice, double shopDiscPct, double itemDiscPct) {
  var total = Math.Clamp(shopDiscPct + itemDiscPct, 0, 90);
  var raw = basePrice * (1 - total / 100.0);
  return Math.Max(0, (int)Math.Ceiling(raw));
}
```

8.4 解锁判断（优先级从上至下，遇到失败立即返回）
- 职业 → 等级 → 账户Flag → 道具使用 → 前置技能；message 为商品 unlock.message 优先，否则通用文案

11. 错误码与提示语
--------------------------------
- NOT_VISIBLE：该职业不可见
- LOCKED：未满足解锁条件（message 返回 unlock.message 或默认原因）
- LIMIT_REACHED：达到限购
- NO_FUNDS：余额不足
- LEARN_FAIL：学习失败（包含 SkillLearningManager 返回的 message）
- INTERNAL_ERROR：内部错误（保底）

提示语建议：
- 职业不匹配：该商品仅限 {Professions} 购买
- 等级不足：需要等级 {X}
- 未满足账户条件：请先完成相关成就/事件
- 请先使用指定道具：{itemName}
- 缺少前置技能：需要已掌握 {skillName}
- 达到限购：已达购买上限
- 余额不足：{currency} 不足

12. 测试计划与验收标准
--------------------------------
12.1 单元测试（≥31）
- 定价/折扣（5）：纯店铺折扣、纯商品折扣、组合折扣、上限 90%、向上取整
- 限购（8）：纯日限购、纯账号限购、纯角色限购、组合并列、跨日重置、计数更新顺序、售罄判定
- 解锁（8）：职业、等级、账户 Flag、道具使用（ItemsUsed）、前置技能、message 覆盖
- 购买效果（6）：learn_skill 成功/失败回滚、grant_item 入背包、余额校验、已学习标记
- 背包使用（4）：使用技能书学习、设置账户 Flag、记录 ItemsUsed、重复使用处理

12.2 集成测试（≥8）
- GetShopView → Purchase → Inventory → UseBook → 再次 GetShopView（解锁链路）
- 双角色在账号限购下的并列行为
- 同角色在日限购 + 角限购交错下的表现
- 价格显示（原价+折扣价）一致性

12.3 验收标准
- 所有新增测试通过，覆盖上述规则
- 购买流程原子且可回滚
- 限购/解锁/价格在 UI 与后端一致
- 背包使用技能书能正确学习技能并产生 Flag

13. 性能与容量规划
--------------------------------
- 商店商品：≤12（MVP）
- items 定义：百级规模
- 视图计算：O(N)（N=商品数），每次打开面板计算一次即可
- 购买 TPS：单机无竞争，平均 < 10/s
- 存储：AccountShopState JSON 序列化体量很小

15. 风险与缓解
--------------------------------
- 自然日重置的时区问题：使用本地时间（IClock.Now），文档注明；未来服务器权威时切换 UTC
- LearnSkill 失败回滚：已实现货币返还；记录 LEARN_FAIL 事件用于诊断
- 解锁链过深导致混乱：UI 显示清晰的锁定原因；文案来自 unlock.message
- 配置错误：StoreRepository 校验 + 启动时统一报表（缺失 skillId/itemId）
