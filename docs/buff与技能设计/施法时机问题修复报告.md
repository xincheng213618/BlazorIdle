## 问题描述 / Problem Description

### 用户报告的现象 / User-Reported Symptoms

根据战斗日志：
```
[6.00s] test123 火球术 (普攻) 对 fire_mage_1 造成 23 伤害，fire_mage_1 HP：247
[11.10s] test123 冰霜箭 (施法) 对 fire_mage_1 造成 64 伤害，fire_mage_1 HP：159
```

**问题：** 为什么 [6.00s] 普攻后，下一次攻击要等到 [11.10s]？中间有 5.1 秒的空窗期。

### UI 表现 / UI Behavior

用户在 UI 上观察到：
1. [6.00s] 普通攻击完成
2. **6.00s 之后攻击进度条又开始走**（准备下一次普攻）
3. **进度条满了（应该是~9秒），但什么都没发生**
4. [11.10s] 才开始施法冰霜箭
5. [~12.9s] 冰霜箭造成伤害（11.10 + 1.8秒施法时间）

### 预期行为 / Expected Behavior

根据设计文档和用户理解：
1. [6.00s] 普通攻击完成后，玩家应该有 3 点法力
2. [6.00s] 应该**立即**开始施放冰霜箭（1.8秒施法时间）
3. [7.80s] 冰霜箭应该造成伤害

## 根本原因分析 / Root Cause Analysis

### 技术原因 / Technical Root Cause

在 `MultiBattleInstance.cs` 的 `ProcessCharacterActions` 方法中：

```csharp
// Line 478-482
var atkCount = tracks.AttackTrack.CollectTriggers(now);
for (int i = 0; i < atkCount; i++)
{
    ProcessAttackDecisionPoint(charId, character, now);
}
```

**关键问题：** `ProcessAttackDecisionPoint` **只在 AttackTrack 触发时**被调用。

### 执行流程分析 / Execution Flow Analysis

#### 当前（错误）流程：
```
[6.00s] AttackTrack 触发
  ↓
ProcessAttackDecisionPoint()
  ↓
没有施法技能可用（可能资源不足或冷却中）
  ↓
执行普通攻击（火球术）
  ↓
PostAttack 窗口执行瞬发技能
  ↓
**结束，等待下一次 AttackTrack 触发**
  ↓
AttackTrack 继续计时（约 3 秒攻击间隔）
  ↓
[9.00s] AttackTrack 再次触发
  ↓
ProcessAttackDecisionPoint()
  ↓
检查施法技能，发现冰霜箭可用（有足够法力）
  ↓
开始施法（1.8秒）
  ↓
[~10.8s] 施法完成，造成伤害
```

**问题在于：** 普攻完成后，系统没有立即检查是否应该开始施法，而是等到下一次 AttackTrack 触发（约3秒后）。

#### 正确流程：
```
[6.00s] AttackTrack 触发
  ↓
ProcessAttackDecisionPoint()
  ↓
没有施法技能可用
  ↓
执行普通攻击（火球术）
  ↓
PostAttack 窗口执行瞬发技能
  ↓
**【修复点】立即调用 TryStartCasting()**
  ↓
检查是否有可用的施法技能
  ↓
发现冰霜箭可用（有足够法力）
  ↓
立即开始施法（暂停 AttackTrack）
  ↓
[7.80s] 施法完成，造成伤害
```

### 为什么之前没发现这个问题？ / Why Wasn't This Caught Earlier?

1. **施法时机调用点缺失**：
   - `TryStartCasting` 在 `HandlePlayerCastComplete` 中被调用（施法完成后）
   - `TryStartCasting` 在 `ResetBattle` 中被调用（战斗开始时）
   - **但没有在普攻完成后调用**

2. **测试覆盖不足**：
   - 现有的 Phase 8 测试主要测试 `CastingController` 本身
   - 缺少完整的战斗流程集成测试（普攻 → 资源积累 → 自动施法）

## 修复方案 / Solution

### 代码修改 / Code Changes

**文件：** `BlazorIdle.Shared/Game/MultiBattleInstance.cs`  
**位置：** `ProcessAttackDecisionPoint` 方法，PostAttack 窗口结束后

```csharp
// Phase 7: PostAttack 窗口触发器
// Phase 7: PostAttack window triggers
ProcessWindowTriggers(charId, "OnPostAttackWindow", normalAttackSkillId, isCasterPlayer: true);

// FIX: 普攻完成后立即尝试施法（如果有可用的施法技能）
// FIX: After normal attack, immediately try to start casting (if there's an available cast skill)
// 这样可以避免等待下一次 AttackTrack 触发才检查施法
// This avoids waiting for the next AttackTrack trigger to check for casting
TryStartCasting(charId, now);
```

### 修复逻辑 / Fix Logic

`TryStartCasting` 方法会：
1. 检查角色是否已在施法（如果是，返回 false）
2. 获取 CharacterData 和战斗上下文
3. 通过 `WindowExecutor.ExecuteWindow(WindowType.PreAttack, ...)` 检查是否有施法技能可用
4. 如果有：
   - 计算急速加成
   - 调用 `CastingController.StartCast()`
   - 暂停 AttackTrack
   - 记录 CastStartEvent
   - 返回 true
5. 如果没有：
   - 返回 false
   - AttackTrack 继续正常计时

**关键点：** 如果开始施法，AttackTrack 会被暂停；如果没有可用施法技能，AttackTrack 正常继续，不会影响原有行为。

  - WindowExecutor 已有缓存优化（Phase 9）
- **结论**：性能影响可忽略不计

#### 风险 2：行为变化 ✅ 已验证

  - 新行为：立即施法（符合设计）
  - 所有单元测试通过，没有破坏性变更
- **结论**：变化是预期的修复，不是副作用

#### 风险 3：冷却和资源管理 ✅ 已验证
- **风险**：可能绕过冷却或资源检查
- **评估**：不存在此风险

  - WindowExecutor 使用相同的 `CooldownManager` 和 `ResourceManager`

## 总结 / Summary

### 问题 / Problem
普攻完成后，玩家需要等待额外的攻击间隔（~3秒）才会检查是否应该开始施法，导致施法延迟。

### 原因 / Cause
`ProcessAttackDecisionPoint` 只在 AttackTrack 触发时被调用，普攻完成后没有立即重新检查施法技能的可用性。

### 修复 / Fix
在 PostAttack 窗口结束后立即调用 `TryStartCasting(charId, now)`，使玩家在资源充足时可以立即开始施法。
