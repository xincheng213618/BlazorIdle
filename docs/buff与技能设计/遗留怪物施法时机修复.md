## 技术细节 / Technical Details

### 为什么需要两次修复？ / Why Two Fixes?

1. **第一次修复（ccbc51e）：**
   - 目标：修复"配置技能"怪物的施法延迟
   - 范围：`ProcessMonsterSkillAttack` 方法
   - 假设：所有怪物都使用配置技能系统

2. **第二次修复（7fbebc0）：**
   - 目标：修复"遗留"怪物的施法延迟
   - 范围：`ProcessEnemyAttackViaSkillResolver` legacy 路径
   - 原因：发现还有怪物使用旧的攻击系统

### 怎样的怪物是"遗留怪物"？ / What are "Legacy Monsters"?

**遗留怪物特征：**
- `enemy.HasConfiguredSkills()` 返回 `false`
- 没有配置 `castSkillIds` 或 `instantSkillIds`
- 只使用 `GetNormalAttackSkillId()` 返回的技能
- 例如：测试用的简单怪物、早期创建的怪物

**配置技能怪物特征：**
- `enemy.HasConfiguredSkills()` 返回 `true`
- 配置了 `castSkillIds` 和/或 `instantSkillIds`
- 可以使用施法技能和瞬发技能
- 例如：Fire Mage 怪物、高级 Boss

### TryStartMonsterCasting 如何工作？ / How Does TryStartMonsterCasting Work?

```csharp
private bool TryStartMonsterCasting(string enemyId, Enemy enemy, int now)
{
    // 1. 检查是否已在施法
    if (_castingController.IsCastingForCaster(enemyId))
        return false;
    
    // 2. 尝试选择一个施法技能
    var castSkill = _autoCastEngine.SelectMonsterCastSkill(enemy, enemyId, context);
    
    // 3. 如果有施法技能可用
    if (castSkill != null && castSkill.CastTimeSec > 0)
    {
        // 开始施法
        _castingController.StartCast(...);
        track.AttackTrack.Pause(now);
        return true;
    }
    
    // 4. 没有可用施法技能
    return false;
}
```

**关键点：**
- 如果怪物没有配置施法技能，`SelectMonsterCastSkill` 会返回 null
- 遗留怪物调用 `TryStartMonsterCasting` 不会出错，只是会返回 false
- 这样的设计让修复可以安全地应用到所有怪物类型
