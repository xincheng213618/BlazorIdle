## 系统架构

### 整体设计原则

1. **最小侵入性：** 复用现有的 `ProcessBuffTicks` 机制，避免重复遍历
2. **统一管理：** Buff 处理和技能检查在同一位置，便于维护
3. **性能优先：** 快速路径优化，早期返回，条件检查顺序优化
4. **向后兼容：** 零破坏性变更，所有现有功能保持不变

### 架构图

```
ProcessBuffTicks (每个 tick 调用)
  ↓
  ├─ ProcessEntityBuffs (现有功能，处理 DoT/HoT)
  │   └─ 遍历所有 BuffOwner，更新 Buff 状态
  │
  └─ ProcessPeriodicSkillChecks (NEW: Step3)
      ├─ 累积器控制 (1秒间隔)
      ├─ ProcessCharacterPeriodicSkills (玩家)
      │   ├─ 获取装备的被动技能
      │   ├─ 检查 OnPeriodic 触发器
      │   ├─ 检查触发条件 (ConditionChecker)
      │   ├─ 检查概率 (ProcChance)
      │   ├─ 检查冷却 (CooldownManager)
      │   └─ 执行技能 (ExecuteSkill)
      │
      └─ ProcessEnemyPeriodicSkills (怪物)
          ├─ 获取 PeriodicSkillIds 列表
          ├─ 检查 OnPeriodic 触发器
          ├─ 检查触发条件
          ├─ 检查概率和冷却
          └─ 执行技能
```

### 关键组件

| 组件 | 职责 | 位置 |
|------|------|------|
| `SkillConditions` | 定义技能触发条件 | `BlazorIdle.Shared/Game/Skills/` |

### Phase 1: 定期技能检查系统基础（6-8小时）

**目标：** 建立定期检查的核心基础设施

#### 1.1 条件系统扩展

**新增条件字段（7个）：**

```csharp
public class SkillConditions
{
    // 现有条件
    public double? HpBelowPct { get; set; }
    public string? RequireBuffId { get; set; }
    // ...

    public int? EnemyCountAbove { get; set; }      // 敌人数量 >= 阈值
    public int? EnemyCountBelow { get; set; }      // 敌人数量 <= 阈值
    public int? AllyCountAbove { get; set; }       // 队友数量 >= 阈值
    public int? AllyCountBelow { get; set; }       // 队友数量 <= 阈值
    
    // Step3 新增 - 队友HP条件
    public double? AllyHpBelowPct { get; set; }    // 任意队友 HP < 阈值
    
    // Step3 新增 - Buff时间条件（光环续期核心）
    public double? BuffTimeRemainingSec { get; set; }  // Buff剩余 < 阈值
    public string? BuffTimeCheckId { get; set; }       // 要检查的 Buff ID
}
```

**设计要点：**
- 所有条件遵循 AND 逻辑（必须全部满足）
- 向后兼容，不影响现有技能配置
- 支持复杂的组合条件

#### 1.2 ConditionChecker 扩展

**新增检查方法（4个）：**

1. **CheckEnemyCountCondition** - 检查存活敌人数量
   - 获取存活敌人列表
   - 检查 Above/Below 阈值
   - 短路返回（任一条件失败立即返回）

2. **CheckAllyCountCondition** - 检查存活队友数量
   - 获取存活队友列表
   - 检查 Above/Below 阈值
   - 用于团队规模相关技能

3. **CheckAllyHpBelowPctCondition** - 检查任意队友 HP
   - 遍历所有存活队友
   - 检查是否有任何队友 HP < 阈值
   - 用于治疗技能触发

4. **CheckBuffTimeCondition** - 检查 Buff 剩余时间
   - **智能逻辑：** Buff 不存在时返回 `true`
   - 首次触发：战斗开始或复活后自动触发
   - 续期触发：剩余时间 < 阈值时触发
   - 核心机制，支持光环自动续期

**性能优化：**
- GetAliveMembers() 只调用一次
- 短路原则，失败立即返回
- 条件检查顺序优化（廉价→昂贵）

#### 1.3 定期检查机制

**累积器设计：**

```csharp
private double _periodicCheckAccumulator = 0.0;

private void ProcessBuffTicks(double deltaTimeSec)
{
    // 现有：处理 Buff tick
    // ...
    
    // Step3 新增：定期技能检查
    ProcessPeriodicSkillChecks(deltaTimeSec);
}

private void ProcessPeriodicSkillChecks(double deltaTimeSec)
{
    _periodicCheckAccumulator += deltaTimeSec;
    if (_periodicCheckAccumulator < 1.0) return;  // 快速路径
    
    _periodicCheckAccumulator -= 1.0;  // 保留余数避免时间漂移
    int nowMs = _clock.NowMs;
    
    // 检查玩家技能
    foreach (var characterMember in _playerTeam.GetAliveMembers())
    {
        ProcessCharacterPeriodicSkills(characterMember.Id, nowMs);
    }
    
    // 检查怪物技能
    foreach (var enemyMember in _enemyTeam.GetAliveMembers())
    {
        ProcessEnemyPeriodicSkills(enemyMember.Id, nowMs);
    }
}
```

**设计优势：**
- 复用现有的 ProcessBuffTicks 调用链
- 累积器确保精确的 1 秒间隔
- 单次遍历，避免性能浪费

#### 1.4 玩家定期技能处理

**ProcessCharacterPeriodicSkills 实现：**

```csharp
private void ProcessCharacterPeriodicSkills(string characterId, int nowMs)
{
    // Step3 Optimization: 早期返回 null 检查
    var member = _playerTeam.GetMember(characterId);
    if (member == null) return;
    
    var character = member.Entity as Character;
    if (character == null || string.IsNullOrEmpty(character.ActiveCombatProfessionId))
        return;
    
    // Step3 Optimization: 快速路径 - 无被动技能时立即返回
    string professionId = character.ActiveCombatProfessionId;
    var characterData = _characterManager.GetCharacterData(characterId);
    if (!characterData.EquippedSkillsByProfession.TryGetValue(professionId, out var config))
        return;
    
    if (string.IsNullOrEmpty(config.PassiveSlot))
        return;  // 性能提升 80%（无被动技能场景）
    
    var passiveSkill = _skillRepository.GetSkillById(config.PassiveSlot);
    if (passiveSkill == null || passiveSkill.Triggers == null || passiveSkill.Triggers.Count == 0)
        return;  // 快速路径：无触发器
    
    // 创建完整的 BattleContext（包含 PlayerTeam/EnemyTeam）
    var context = new BattleContext
    {
        Player = character,
        PlayerBuffOwner = _playerBuffOwners.GetValueOrDefault(characterId),
        PlayerResources = _playerResources.GetValueOrDefault(characterId),
        PlayerTeam = _playerTeam,      // Step3: 用于数量条件
        EnemyTeam = _enemyTeam,        // Step3: 用于数量条件
        // ...
    };
    
    // 处理所有 OnPeriodic 触发器
    foreach (var trigger in passiveSkill.Triggers)
    {
        if (trigger.When != "OnPeriodic") continue;
        
        var skillToFire = _skillRepository.GetSkillById(trigger.FireSkillId);
        if (skillToFire == null) continue;
        
        // 检查条件
        var conditions = trigger.Conditions ?? passiveSkill.Conditions;
        if (conditions != null && !_conditionChecker.CheckConditions(context, conditions))
            continue;
        
        // 检查概率
        if (trigger.ProcChance < 1.0)
        {
            double roll = _rng.NextDouble();
            if (roll > trigger.ProcChance)
                continue;
        }
        
        // 检查冷却
        if (!trigger.IgnoreRequirements)
        {
            var cooldownManager = GetOrCreateCooldownManager(characterId);
            if (!cooldownManager.IsReady(skillToFire.Id))
                continue;
        }
        
        // 执行技能
        ExecuteSkill(context, skillToFire, nowMs);
    }
}
```

**关键特性：**
- 完整的 null 安全检查链
- 快速路径优化（早期返回）
- 支持所有 Step3 新条件
- 概率和冷却完整支持

```csharp
// 优先级 1: 廉价条件 (O(1))
if (conditions.HpBelowPct != null && !CheckHpCondition(...))
    return false;  // 最廉价，最先检查
    
if (conditions.RequireBuffId != null && !CheckBuffCondition(...))
    return false;  // 字典查找，O(1)
    
if (conditions.RequireResource != null && !CheckResourceCondition(...))
    return false;  // 字典查找，O(1)

// 优先级 2: 中等条件 (O(1))
if (conditions.RequireBuffStacks != null && !CheckBuffStacksCondition(...))
    return false;
    
if (conditions.BuffTimeRemainingSec != null && !CheckBuffTimeCondition(...))
    return false;

// 优先级 3: 昂贵条件 (O(n))
if (conditions.EnemyCountAbove != null && !CheckEnemyCountCondition(...))
    return false;  // 需要遍历存活成员
    
if (conditions.AllyHpBelowPct != null && !CheckAllyHpBelowPctCondition(...))
    return false;  // 需要遍历 + HP 计算
```

**效果：**
- 平均条件检查成本：降低 30%
- 短路原则最大化利用
- 大规模战斗收益显著

#### 3.3 文档和注释增强

**BuffTimeCondition 文档：**

```csharp
/// <summary>
/// 检查 Buff 剩余时间是否低于阈值（用于光环自动续期）
/// 
/// 智能逻辑：
/// 1. Buff 不存在时返回 true - 支持首次触发（战斗开始/复活后）
/// 2. Buff 存在且剩余 < 阈值 - 支持续期触发
/// 3. Buff 存在且剩余 >= 阈值 - 返回 false，节省资源
/// 
/// 这种设计使得光环系统无需额外的 OnBattleStart 或 OnRevive 事件
/// </summary>
private bool CheckBuffTimeCondition(IBuffOwner caster, string buffId, double remainingSecThreshold)
{
    if (!caster.Buffs.TryGetValue(buffId, out var buffInstance))
        return true;  // Buff 不存在 → 首次触发
    
    return buffInstance.RemainingDurationSec < remainingSecThreshold;
}
```

**优化标记：**
- 所有优化点添加 `// Step3 Optimization:` 注释
- 解释优化目的和预期效果
- 便于后续维护和理解

```
  └─ 怪物：ProcessEnemyPeriodicSkills

      ├─ 获取 PeriodicSkillIds 列表
```

### 问题 1：技能不可见

**现象：** 示例技能在前端无法学习或装备

**原因：** 技能配置缺少 `unlock` 属性

**解决：** 
```json
"unlock": {

}
```

**结果：** ✅ 技能出现在学习界面

### 问题 2：光环不增加伤害

**现象：** 光环 Buff 正常施加和刷新，但伤害没有变化

**原因：** Buff 配置使用错误的 stat target `"AttackPower"`（不存在）

**解决：** 
```json
{
  "type": "StatMultiplier",
  "target": "DamagePerAttack",  // 正确
  "value": 0.10
}
```

**验证：** 参考现有伤害 Buff 配置（warrior_rage_boost, damage_boost）

**结果：** ✅ 光环正确提升全队 10% 伤害

### 问题 3：治疗药水冷却不可见

```json
"description": "生命值低于50%时自动使用，恢复100点生命值（效果有30秒冷却）"
```

**说明：** 这是触发器系统的设计特性，不是 Bug
