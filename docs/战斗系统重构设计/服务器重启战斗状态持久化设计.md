# 服务器重启战斗状态持久化设计

## 📋 需求背景

在服务器权威并行模拟架构中，服务器负责运行所有战斗的权威计算。当服务器关闭或重启时，如果不保存战斗状态，会导致：

**问题**：
1. ❌ 玩家正在进行的战斗完全丢失
2. ❌ 服务器重启期间的战斗进度亏损
3. ❌ 玩家体验受损，可能导致严重投诉

**可接受范围**：
- ✅ 服务器关闭期间的战斗进度亏损（不可避免）
- ✅ 重启后恢复到关闭前的战斗状态

**设计目标**：
- 🎯 服务器优雅关闭时自动保存所有活跃战斗状态
- 🎯 服务器重启时自动恢复所有战斗并继续运行
- 🎯 支持热重启（无缝切换）
- 🎯 防止数据损坏和不一致

## 🏗️ 核心设计

### 1. 战斗状态持久化策略

#### 1.1 持久化时机

**定期自动保存**（双重保障）：
- 📌 **方案A**：随心跳保存（每30秒）
  - 优点：简单，与现有心跳机制统一
  - 缺点：最多丢失30秒进度
  
- 📌 **方案B**：高频保存（每5秒）
  - 优点：丢失进度极少
  - 缺点：数据库写入频繁

- 🎯 **推荐方案**：内存缓存 + 定期持久化
  - 内存中持续更新战斗状态
  - 每30秒写入数据库（心跳）
  - 优雅关闭时立即保存内存状态

**触发时机**：

### 2. 服务器启动恢复流程

#### 2.1 启动时自动恢复

```csharp
public class ServerBattleCoordinator : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("ServerBattleCoordinator 启动中...");
        
        // 1. 恢复持久化的战斗
        await RestorePersistedBattlesAsync();
        
        // 2. 开始主循环
        await RunBattleLoopAsync(stoppingToken);
    }
    
    private async Task RestorePersistedBattlesAsync()
    {
        _logger.LogInformation("正在恢复持久化的战斗状态...");
        
        var persistedBattles = await _dbContext.ServerBattles
            .Where(b => b.IsPersisted && 
                       (b.Status == "Running" || b.Status == "Paused"))
            .ToListAsync();
        
        int restoredCount = 0;
        int failedCount = 0;
        
        foreach (var battleRecord in persistedBattles)
        {
            try
            {
                // 反序列化战斗状态
                var battleState = JsonSerializer.Deserialize<BattleStateSnapshot>(
                    battleRecord.StateData);
                
                // 重建战斗实例
                var battle = RebuildBattleInstance(battleState);
                
                // 计算服务器停机期间的时间差
                var downtime = DateTime.UtcNow - battleRecord.LastTickAt;
                
                _logger.LogInformation(
                    $"恢复战斗 {battleRecord.Id}，停机时长: {downtime.TotalMinutes:F2} 分钟");
                
                // 选项1：跳过停机期间（玩家损失停机时间）
                // 直接恢复，继续从当前状态运行
                
                // 选项2：快速追赶（可选，资源消耗大）
                // await FastForwardBattle(battle, downtime);
                
                // 添加到活跃战斗列表
                _activeBattles[battleRecord.Id] = new BattleContext
                {
                    Battle = battle,
                    CharacterId = battleRecord.CharacterId,
                    LastTickTime = DateTime.UtcNow,
                    TickInterval = battleRecord.TickInterval,
                    IsOnline = false // 默认离线，等待玩家上线
                };
                
                restoredCount++;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, 
                    $"恢复战斗 {battleRecord.Id} 失败，将标记为已完成");
                
                // 恢复失败的战斗标记为失败
                battleRecord.Status = "Failed";
                battleRecord.CompletedAt = DateTime.UtcNow;
                
                failedCount++;
            }
        }
        
        await _dbContext.SaveChangesAsync();
        
        _logger.LogInformation(
            $"战斗恢复完成：成功 {restoredCount}，失败 {failedCount}");
    }
}
```

#### 2.2 战斗实例重建

```csharp
private BattleInstance RebuildBattleInstance(BattleStateSnapshot snapshot)
{
    // 1. 重建RNG上下文（关键！）
    var rng = new RngContext();
    rng.SetSeed(snapshot.BattleState.RngSeed);
    rng.SetIndex(snapshot.BattleState.RngIndex);
    
    // 2. 重建时钟
    var clock = new Clock();
    clock.SetElapsedTime(snapshot.BattleState.ClockElapsedMs);
    
    // 3. 重建玩家队伍
    var playerTeam = new BattleTeam();
    foreach (var memberData in snapshot.BattleState.PlayerTeam.Members)
    {
        var member = new BattleActor
        {
            CharacterId = memberData.CharacterId,
            CurrentHp = memberData.CurrentHp,
            MaxHp = memberData.MaxHp,
            // ... 其他属性
        };
        playerTeam.AddMember(member);
    }
    
    // 4. 重建敌人队伍
    var enemyTeam = new BattleTeam();
    // ... 类似玩家队伍
    
    // 5. 重建战斗实例
    var battle = new BattleInstance(
        playerTeam, 
        enemyTeam, 
        rng, 
        clock,
        _gameConfig);
    
    // 6. 恢复战斗进度
    battle.SetCurrentWave(snapshot.BattleState.CurrentWave);
    battle.RestoreProgress(snapshot.BattleState.DungeonProgress);
    
    return battle;
}
```

#### 3.1 版本兼容性策略

```csharp
public class BattleStateVersion
{
    public const string CURRENT_VERSION = "1.0.0";
    
    public static bool IsCompatible(string savedVersion)
    {
        // 简单策略：主版本号必须一致
        var current = new Version(CURRENT_VERSION);
        var saved = new Version(savedVersion);
        
        return current.Major == saved.Major;
    }
}

// 恢复时检查版本
if (!BattleStateVersion.IsCompatible(snapshot.Metadata.Version))
{
    _logger.LogWarning(
        $"战斗 {battleRecord.Id} 版本不兼容：" +
        $"保存版本 {snapshot.Metadata.Version}，" +
        $"当前版本 {BattleStateVersion.CURRENT_VERSION}");
    
    // 版本不兼容，放弃恢复
    battleRecord.Status = "Abandoned";
    battleRecord.CompletedAt = DateTime.UtcNow;
    continue;
}
```

### 4. 数据清理策略

#### 4.1 自动清理过期战斗

```csharp
public class BattleCleanupService : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            await CleanupExpiredBattlesAsync();
            
            // 每小时执行一次
            await Task.Delay(TimeSpan.FromHours(1), stoppingToken);
        }
    }
    
    private async Task CleanupExpiredBattlesAsync()
    {
        var cutoffDate = DateTime.UtcNow.AddDays(-7); // 7天前
        
        // 删除已完成且超过7天的战斗记录
        var expiredBattles = await _dbContext.ServerBattles
            .Where(b => b.CompletedAt < cutoffDate)
            .ToListAsync();
        
        _dbContext.ServerBattles.RemoveRange(expiredBattles);
        await _dbContext.SaveChangesAsync();
        
        _logger.LogInformation(
            $"清理了 {expiredBattles.Count} 条过期战斗记录");
    }
}
```

## ⚠️ 注意事项

### 风险与对策

**风险1：保存过程中服务器崩溃**
- 对策：使用数据库事务，全部成功或全部回滚
- 对策：保留上一次成功的保存点

**风险2：大量战斗同时保存导致性能问题**
- 对策：分批保存（每次最多100个）
- 对策：使用异步批量插入

**风险3：战斗状态数据不一致**
- 对策：保存前验证状态完整性
- 对策：恢复后重新验证逻辑正确性

**风险4：数据库膨胀**
- 对策：定期清理过期数据
- 对策：压缩JSON数据
- 对策：考虑使用Redis等内存数据库

### 最佳实践

1. **始终使用事务**：确保数据一致性
2. **记录详细日志**：便于排查问题
3. **定期备份数据库**：防止数据损坏
4. **监控持久化性能**：发现性能瓶颈
5. **测试各种场景**：包括异常情况
